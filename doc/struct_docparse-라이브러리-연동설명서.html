3모든 언어에 공통인 규칙

3-1. lib/ 폴더는 통째로 — 라이브러리가 "자기 옆"을 본다

라이브러리는 pdfium · onnxruntime · OCR 모델을 자기 파일이 있는 폴더에서 먼저 찾는다(그다음 실행 파일 옆). 그래서 lib/ 안 파일을 흩어 놓지 말고 폴더째 두면 된다. 다른 곳에 두었다면 열 때 옵션으로 알려 준다:

json
{"runtime": {"pdfium": "/opt/x/libpdfium.so", "onnxruntime": "/opt/x/libonnxruntime.so"},
 "ocr": {"model_dir": "/opt/x/models/ocr"}}
Windows 에서 다른 버전 onnxruntime.dll(예: 시스템 폴더의 1.17)이 먼저 잡히면 OCR 이 실패한다. 묶음의 onnxruntime 을 lib\ 에 그대로 두면 그것을 쓴다. 같은 프로그램이 이미 다른 onnxruntime 을 쓰고 있다면(환경변수 ORT_DYLIB_PATH) 그 값을 따른다 — 이 라이브러리는 ort 2.0.0-rc.10 이라 1.22 이상이어야 한다(1.22 미만은 거절, 더 새것은 경고만 — SimpleRAG Windows 배포본은 1.29).

3-2. 문자열은 전부 UTF-8 (끝에 0)

  • 경로 · 옵션 JSON · 결과 · 오류문 모두 UTF-8.
  • Windows C/C++ 주의: main(argc, argv) 의 argv 는 시스템 코드 페이지(한국어 Windows 는 CP949)라 한글 경로를 그대로 넘기면 -1("UTF-8 이 아닙니다")이 난다. GetCommandLineW + WideCharToMultiByte(CP_UTF8, …) 로 바꿔 넘긴다(6장 예제에 들어 있음).
  • Java(JNA)는 String 을 운영체제 기본 인코딩으로 바꾸므로, 바인딩은 byte[](UTF-8 + 0)로 넘긴다.

3-3. 받은 문자열은 sdp_free 로 돌려준다

char** out 으로 받은 결과는 라이브러리가 할당한 것이라 반드시 sdp_free(out). 언어 쪽 free 를 쓰면 안 된다. 예외: sdp_version() · sdp_last_error() 가 돌려준 글은 해제하지 않는다(라이브러리가 쥐고 있음).

3-4. 반환 코드

코드이름뜻
0SDP_OK성공 (평문 폴백으로 읽은 것도 0 — 결과의 format: "legacy")
-1SDP_EINVAL널 포인터 · 잘못된 JSON · 모르는 옵션 · UTF-8 아닌 글
-2SDP_EIO파일 없음 · 열 수 없음
-3SDP_EPARSE구조 파서와 평문 추출이 모두 실패(깨진 파일, OCR 끈 스캔 PDF 등)
-4SDP_EUNSUPPORTED지원 안 하는 형식, OCR 끈 상태의 그림 파일
-5SDP_EOCROCR 을 쓸 수 없거나 OCR 중 실패
-7SDP_ERUNTIMEpdfium 적재 실패(PDF 속성 · 쪽 글 함수)

3-5. 열 때 옵션 JSON — 빠진 키는 기본값

json
{
  "ocr": {
    "enabled": true,          // 기본 true — OCR 켬/끔
    "images": true,           // 그림 파일(.png .jpg .tif .bmp)도 OCR
    "mode": "inline",         // inline = 파싱 중 바로 OCR / deferred = 캐시만 보고 남은 쪽은 ocr.pending 으로
    "model_dir": "…",         // 기본: 라이브러리 옆 models/ocr
    "cache_dir": "…",         // OCR 결과 캐시 폴더(없으면 프로세스 메모리)
    "threads": 4, "max_pages": 100,
    "layout": true,           // OCR 줄 구조 분석(다단 · 문단 · 제목 · 목록 · 머리말) — 끄면 화면 한 줄이 문단 하나
    "arena": true,            // 0.1.1~ OCR 메모리 아레나 켬 + 실행마다 줄이기(인식이 빨라짐) — false 면 0.1.0 과 같은 방식
    "page_cap": "a4",         // 0.1.1~ A4 보다 큰 PDF 쪽 · 그림을 A4 크기로 줄여 OCR — "none" 이면 원래 크기
    "image_cap": false,       // 0.1.1~ 그림 파일에도 page_cap 을 쓰나(기본 끔 — 4K 화면 캡처 작은 글자가 나빠짐)
    "page_up": true,          // 0.1.1~ A4 보다 작은 PDF 쪽(A5 · A6 등)을 최대 1.4배 해상도로 그려 OCR — false 면 200dpi 그대로
    "orient": true,           // 0.1.1~ 누운 · 뒤집힌 스캔 쪽을 바로 세워 OCR(쪽 방향 보정) — false 면 이전과 같음
    "orient_flip": false      // 0.1.1~ 바로 선 쪽도 뒤집힘(180°)을 확인 — 기본 끔(누운 쪽만 판별). 켜면 바로 선 쪽마다 0.02~0.31초가 붙는다
  },
  "pdf": {"tables": true, "infer_headings": false},
  "runtime": {"pdfium": "…", "onnxruntime": "…"},
  "log": {"level": "warn"},   // warn | info | off
  "extra_text": true,         // 0.2.0~ 본문 밖 글(PDF 글상자 · 서식 칸 · docx 메모 · SmartArt) 읽기 — false 면 0.1.x 와 같은 본문
  "chunk": {                  // 0.3.0~ 청킹 기본값 — 여기 적어도 켜지지는 않는다. 켜는 것은 호출마다(3-9)
    "tokenizer": "…/tokenizer.json",  // e5 토크나이저 파일. unit 이 tokens 면 필요
    "unit": "tokens",         // tokens = 토큰 수로 잼 / chars = 글자 수로 잼(아래 크기 값이 모두 글자 수 뜻)
    "mode": "structured",     // structured = 절 단위 / fixed = 고정 크기
    "tokens": 128, "overlap": 16, "min_tokens": 16,
    "table_header_max_tokens": 64, "table_whole": 384,
    "overflow_ratio": 1.0, "sentence_split": false, "hard_max": 510,
    "prefix": true, "prefix_max_chars": 80
  }
}

실제 JSON 에는 주석(//)을 넣으면 안 된다. 모르는 키는 -1 로 거절한다(오타를 조용히 넘기지 않게). 그래서 arena · page_cap · image_cap · page_up · orient · orient_flip 을 0.1.0 라이브러리에 넘기면 열기가 실패한다 — 라이브러리와 함께 올린다. 쪽 방향 보정으로 돌려 읽은 쪽은 OCR 캐시에 rot(시계 방향 각도)이 함께 남고, 줄 좌표는 바로 선 쪽 기준이다. 자세한 근거는 plan/OCR쪽방향보정_설계서_20261117.html. 세 옵션은 sdp_set_option 으로 바꿔도 된다(아레나를 바꾸면 다음 OCR 때 엔진을 다시 만든다). 자세한 근거는 plan/OCR속도개선_설계서_20261117.html.

extra_text(0.2.0~, 기본 켬)는 사이냅이 읽는 본문 밖 글을 함께 읽는다 — PDF 글상자 주석(숨긴 것도) · PDF 서식 칸 값 · docx 메모 · pptx/docx SmartArt. 이 블록은 source 가 "extra" 다. OCR 하는 스캔 쪽은 보이는 주석을 OCR 이 읽으므로 숨긴 주석만 글로 붙는다. 실행 중에는 sdp_set_option(h, "extra_text", "false") 로 끈다(묶음 없는 맨 위 키). 0.1.x 라이브러리에 넘기면 모르는 키라 열기가 실패한다. 근거 · 사이냅 비교는 plan/본문밖글읽기_설계서_20261118.html.

3-6. OCR 켜기·끄기 세 단계

  1. 열 때 — {"ocr":{"enabled":false}}
  2. 실행 중 — sdp_set_option(h, "ocr.enabled", "false") (끄면 OCR 엔진도 내려 메모리를 돌려준다)
  3. 호출마다 — sdp_parse(h, path, "{\"ocr\":{\"enabled\":false}}", &out)

모델 파일이 없으면 켜 놓아도 꺼진 것처럼 동작하고, sdp_get_status 의 ocr.reason 이 "models_missing" 이다.

3-8. 스레드 · 핸들 · 판

  • 핸들 하나를 여러 스레드가 같이 써도 된다(PDF · OCR 은 안에서 차례를 지킨다).
  • 옵션은 프로세스에 한 벌 — 핸들을 여럿 열면 마지막에 연 옵션을 함께 쓴다.
  • 열자마자 sdp_abi_version() == 1 인지 확인한다(함수 모양이 바뀌면 이 숫자가 바뀐다).
  • blocks_version 이 바뀌면 결과 모양이 달라진 것 — 저장해 둔 결과를 다시 만들지 판단할 때 쓴다.
  • 청크를 저장해 쓰면 chunk_version(0.3.0~)도 함께 적어 두고, 둘 중 하나라도 바뀌면 다시 자른다.

3-9. 청크로 받기 — 블록 단위 청킹 0.3.0~

0.3.0 부터 쓸 수 있다. 0.2.x 라이브러리에 chunk 옵션을 넘기면 모르는 옵션이라 -1 이 나고, sdp_chunk 함수도 없다 — 라이브러리와 바인딩을 함께 올린다. 설계 · 시험: plan/블록청킹_DLL옵션_설계서_20261127.md.

블록을 받은 뒤 검색용으로 잘게 자르는 일(청킹)을 라이브러리가 대신 한다. SimpleRAG 가 쓰는 규칙 그대로다.

  1. 제목 블록의 수준으로 절을 나눈다(머리글 · 바닥글 · 쪽 번호 · 목차 블록은 뺀다).
  2. 작은 절은 크기(tokens) 안에서 이어 묶고, 큰 절은 제목 · 블록 · 표 행 단위로 자른다.
  3. 표는 행 경계에서 자르고 조각마다 머리글 행을 다시 붙인다. 작은 표(table_whole 이하)는 통째로 둔다.
  4. 청크 앞에 [문서 제목 > 절 > …] 접두를 붙이고, 청크가 실제로 시작하는 쪽을 찾아 적는다.
  5. 510 토큰(hard_max)을 넘는 청크는 다시 자르고, min_tokens 보다 짧은 청크는 버린다.

① 켜기 — 호출마다. 열 때 옵션(3-5)의 chunk 는 기본값일 뿐이고, sdp_parse 의 호출 옵션에 chunk 를 줄 때만 자른다. 호출 옵션 chunk 는 true(기본값으로 켬) · 객체(켬 + 이 호출만 덮어쓰기, "enabled": false 면 끔) · false(끔). tokens 만 바꾸고 overlap 을 주지 않으면 overlap = max(8, tokens/8) 로 따라간다(SimpleRAG 설정과 같은 규칙). 실행 중에 기본값을 바꾸려면 sdp_set_option(h, "chunk.tokens", "256"). overlap 이 tokens 이상이거나 hard_max 가 tokens 보다 작은 등 어긋난 값은 -1.

c
/* 열 때 — 토크나이저 경로와 기본 크기 */
sdp_open("{\"chunk\":{\"tokenizer\":\"models/e5-small-ko/tokenizer.json\"}}", NULL, NULL, &h);
/* 호출마다 — 켜기만 */
sdp_parse(h, path, "{\"chunk\":true}", &out);
/* 이 호출에서만 크기를 바꿔 */
sdp_parse(h, path, "{\"chunk\":{\"enabled\":true,\"tokens\":256}}", &out);

② 길이를 무엇으로 재나. 기본은 e5 토크나이저의 토큰 수다(tokenizer.json). 토크나이저는 두 가지에 쓴다.

  • 길이 재기 — tokens(목표 크기) · hard_max(상한) · min_tokens · table_whole · table_header_max_tokens 와 비교할 때, 결과의 tokens 값.
  • 긴 줄 자르기 — 한 줄이 혼자 크기를 넘거나 청크가 상한을 넘으면 토큰 창으로 자른 뒤 글로 되돌린다(고정 크기 모드도 같다). 그래서 SimpleRAG 와 같은 청크를 내려면 같은 토크나이저가 꼭 필요하다.

토큰으로 재는 까닭은 청크가 들어갈 임베딩 모델(e5)이 512 토큰까지만 읽기 때문이다(hard_max 510 = 512 − 시작 · 끝 표시 2). 임베딩 · 검색에는 쓰지 않으므로 모델 파일(model.onnx)은 필요 없고 tokenizer.json 하나만 있으면 된다. 파일을 못 읽으면 열기가 아니라 첫 청킹 호출이 -1 로 실패한다 — 청킹을 안 쓰는 프로그램은 영향이 없다. 토크나이저는 처음 청킹할 때 한 번 읽는다(17MB 파일 약 0.7초).

모델 입력 한계 ≠ 청크 크기. 크기 값은 둘이고 따로 움직인다.
  • tokens — 실제로 자르는 크기(목표, 기본 128). 청크는 이 정도로 나온다.
  • hard_max — 넘으면 안 되는 상한(기본 510). 모델 한계를 넘는 청크가 생기지 않게 막는 안전장치일 뿐이다.
모델 한계가 정하는 것은 hard_max 하나다. 8k · 10k 토큰을 받는 모델이라도 문서를 그 크기로 한꺼번에 자르지 않는다 — 청크 하나가 벡터 하나라서, 크게 자르면 여러 조항 · 주제가 한 벡터에 섞여 구체적 질문과 잘 맞지 않고, 근거의 쪽 · 조항도 흐려지고, 답변 LLM 프롬프트도 금방 찬다. 긴 입력 모델도 tokens 는 보통 256~512, 긴 한계는 "가끔 긴 표 · 문단이 와도 잘리지 않는" 여유로 쓴다.
json
{"chunk": {"tokenizer": "…/bge-m3/tokenizer.json", "tokens": 256, "hard_max": 8190}}   // 청크는 256 안팎, 8190 은 상한일 뿐
hard_max 를 510 그대로 둬도 된다 — tokens 가 256 이면 510 에 닿는 청크가 거의 없다.

토크나이저 없이 — 글자 수("unit": "chars"). 파일이 없어도 된다. 이때는 tokens · overlap · min_tokens · table_whole · hard_max 등 모든 크기 값이 글자 수 뜻이고, 긴 줄도 글자 창으로 자른다.

  • SimpleRAG 와 같은 청크가 아니다 — 토큰 기준으로 만든 색인과 섞어 쓰면 안 되고, 바꾸면 다시 색인한다.

3-10. 부모-자식으로 쓰기 — 검색은 청크, LLM 에는 절 0.3.0~

청크는 검색이 잘 되도록 작게(128 토큰) 자른 것이라, 그대로 LLM 에 넘기면 앞뒤 문맥이 모자랄 수 있다. 그래서 검색은 작은 청크(자식)로 하고, LLM 에는 그 청크가 속한 절(부모)을 넓혀 넘긴다. 결과의 section_id 가 같은 청크끼리가 같은 절이므로, 검색된 청크의 section_id 로 묶어 같은 절 형제 청크를 붙이면 된다. SimpleRAG 가 이렇게 한다(rust/simplerag/src/retrieve.rs 의 expand · build_parent, 설정 generation.parent: section · parent_max_tokens: 400).

  1. 색인할 때 청크마다 text 와 함께 문서 식별자 · no · section_id · tokens 를 저장한다(벡터 DB payload 등). 쪽(page)도 남기면 근거 표시에 쓴다.
  2. 검색 — 평소처럼 청크로 검색 · 리랭킹해 순서대로 받는다.
  3. 묶기 — 검색된 청크마다 (문서, section_id) 를 키로 한다. 같은 키가 또 나오면 건너뛴다(같은 절을 두 번 넣지 않게).
  4. 넓히기 — 같은 키의 형제 청크를 no 순서로 모아, 검색된 청크를 가운데 두고 뒤 · 앞을 번갈아 붙인다. 합이 상한(예: 400 토큰)을 넘기 직전에 멈춘다.
  5. 잇기 — 형제 청크 첫 줄의 접두 [문서 > 절] 은 떼고, 맨 앞에 접두 한 줄만 둔다.
  6. 이렇게 만든 부모 글을 top_k 개까지 LLM 컨텍스트로 넘긴다. 근거 표시는 자식 청크(검색된 것)의 쪽 · 경로를 쓰면 된다.

코드(Python) — SimpleRAG 와 같은 규칙. 형제 길이는 각 청크의 tokens 값을 쓴다(접두 포함이라 조금 넉넉히 잡힌다).

python
def split_prefix(text):
    """청크 첫 줄 "[문서 > 절]" 을 떼어 (접두, 본문) 으로"""
    first, _, rest = text.partition("\n")
    if first.startswith("[") and first.endswith("]"):
        return first, rest.strip()
    return "", text.strip()


def expand(hits, chunks_of, top_k=3, max_tokens=400):
    """검색된 자식 청크 → 절 단위 부모 글
    hits      = 검색 · 리랭킹 순서의 [(문서 id, 청크 dict)]
    chunks_of = 문서 id → 그 문서의 chunks 목록(색인 때 저장한 것)"""
    out, seen = [], set()
    for doc, c in hits:
        sid = c["section_id"]
        key = (doc, sid) if sid is not None else (doc, "no", c["no"])
        if key in seen:                       # 같은 절은 한 번만
            continue
        seen.add(key)
        sibs = [x for x in chunks_of[doc] if sid is not None and x["section_id"] == sid] or [c]
        sibs.sort(key=lambda x: x["no"])
        i = next(k for k, x in enumerate(sibs) if x["no"] == c["no"])
        prefix, _ = split_prefix(c["text"])
        chosen, total = {i}, sibs[i]["tokens"]
        lo, hi = i - 1, i + 1
        while True:                           # 뒤 · 앞을 번갈아, 상한 직전까지
            grew = False
            if hi < len(sibs) and total + sibs[hi]["tokens"] <= max_tokens:
                chosen.add(hi); total += sibs[hi]["tokens"]; hi += 1; grew = True
            if lo >= 0 and total + sibs[lo]["tokens"] <= max_tokens:
                chosen.add(lo); total += sibs[lo]["tokens"]; lo -= 1; grew = True
            if not grew:
                break
        keys = sorted(chosen)
        body = "\n".join(split_prefix(sibs[k]["text"])[1] for k in keys)
        out.append({"doc": doc, "section_id": sid, "child_no": c["no"],
                    "nos": [sibs[k]["no"] for k in keys], "tokens": total,
                    "text": f"{prefix}\n{body}" if prefix else body})
        if len(out) >= top_k:
            break
    return out

① 만드는 규칙. 둘 다 SHA-256(글을 UTF-8 바이트로)의 앞 16자리(소문자 16진수, 64비트)다. 어느 언어에나 SHA-256 이 기본으로 있어 같은 값을 다시 만들 수 있다.

  • hash = SHA-256(text) 앞 16자리. 정리 없음.
  • body_hash = SHA-256(본문) 앞 16자리. 본문은 이렇게 만든다.
    1. text 를 줄(\n)로 나눈다.
    2. 접두 줄을 뺀다. 접두 줄 = 공백을 정리하면 [제목] 이거나, [제목 > 로 시작해 ] 로 끝나는 줄(제목 = 결과의 title). 작은 절을 묶은 청크는 접두 줄이 여러 개라 모두 뺀다. 본문의 [별표 1] 같은 줄은 제목으로 시작하지 않으므로 남는다. 제목이 비었으면 첫 줄이 […] 일 때만 뺀다.
    3. 남은 줄을 이어 연속 공백(띄어쓰기 · 줄바꿈 · 탭)을 한 칸으로 줄이고 앞뒤를 자른다.
    4. 그래서 빈 글이 되면(목차처럼 접두 줄만 든 청크) 접두를 떼지 않은 text 를 3 처럼 정리해 쓴다 — 접두가 곧 내용이라, 떼면 상관없는 청크들이 모두 "빈 글" 하나의 지문으로 묶이기 때문이다(샘플 문서에서 실제로 17개가 그렇게 묶였다).
python
import hashlib

def sha16(s):
    return hashlib.sha256(s.encode("utf-8")).hexdigest()[:16]

def squash(s):                                    # 연속 공백 → 한 칸, 앞뒤 자르기
    return " ".join(s.split())

def body_of(text, title):
    t, kept = squash(title), []
    for i, line in enumerate(text.split("\n")):
        l = squash(line)
        bracket = l.startswith("[") and l.endswith("]")
        if t:
            prefix = bracket and (l == f"[{t}]" or l.startswith(f"[{t} > "))
        else:
            prefix = bracket and i == 0               # 제목이 없으면 첫 줄만 접두로
        if not prefix:
            kept.append(line)
    return squash(" ".join(kept)) or squash(text)  # 접두뿐이면 접두를 남긴 글로

# c = doc["chunks"][k] 일 때
assert c["hash"] == sha16(c["text"])
assert c["body_hash"] == sha16(body_of(c["text"], doc["title"]))

이 코드로 만든 값이 라이브러리 값과 12,075개 청크 모두 같았다(SimpleRAG 샘플 41건 × 설정 4가지 — 기본 · 접두 끔 · 글자 400 · 고정 크기). 그래도 연동에서는 라이브러리가 준 값을 그대로 쓰는 것이 안전하다 — 언어마다 따로 구현하면 규칙이 조금씩 어긋나기 쉽다. 위 코드는 0.3.0 으로 만든 청크에 지문을 붙이거나 값을 검사할 때 쓴다.

def dedup(hits):
    """hits = 검색 순서의 [{"doc": 문서, "chunk": 청크}] → 같은 본문은 하나로, 나머지는 also 에"""
    out, first = [], {}
    for h in hits:
        k = h["chunk"]["body_hash"]
        if k in first:
            first[k]["also"].append(h["doc"])      # 같은 내용 · 다른 문서
            continue
        first[k] = dict(h, also=[])
        out.append(first[k])
    return out

3-13. 글자층에서 빠진 숫자 고치기 — 강제 OCR 0.4.0~

0.4.0 부터. 어떤 PDF 는 글자층에서 숫자가 빠져 있다 — "제8조제1항" 이 "제 조제 항", "1인당 3만원" 이 "인당 만원" 으로 나온다. 글자층이 있으니 스캔 쪽 판정(3-6)에 걸리지 않아 OCR 되지 않는다. 호출 옵션으로 쪽을 골라 글자층이 있어도 OCR 하고, 그 글로 고친다. 기본은 꺼짐(옵션을 주지 않으면 0.3.x 와 같다).

fill 이 고치는 규칙(DecideRAG ocrfix.py 와 같다)

  1. 쪽 전체를 OCR 한다. 보통 OCR 과 달리 글자층과 겹친 줄을 빼지 않는다. 결과는 OCR 캐시의 따로 칸(full)에 두어, 다음 호출은 OCR 없이 고친다.
  2. 블록마다 글자층 글과 쪽 OCR 글에서 글자(한글 · 영문 · 한자)만 뽑아 맞춘다(숫자 · 기호 · 공백은 빼고).
  3. 맞은 글자가 90% 미만이거나 OCR 쪽에서 흩어져 맞으면(블록 글자 수의 1.2배 + 3 보다 넓으면) 그 블록은 그대로 둔다. 글자 4개 미만인 블록도 그대로.
  4. 블록에서 이웃한 두 글자가 OCR 에서도 바로 이웃하고, OCR 쪽 두 글자 사이에 숫자가 있고(줄바꿈은 없고), 글자층 쪽 틈에는 숫자가 없으면 → 그 틈만 OCR 것으로 바꾼다. 다른 틈(띄어쓰기)은 글자층 그대로.
  5. 표 블록 · 이미 OCR 글인 블록은 건드리지 않는다. 고친 블록의 source 는 "ocr_fix".

결과 — ocr.forced 에 {"pages", "mode", "fixed", "tried"}(fixed = 고친 블록 수, replace 면 바꾼 쪽 수 · tried = 그 쪽들에서 고쳐 보려 한 블록 수). 고를 쪽이 없으면 pages: [], PDF 가 아니면 {"skipped": "PDF 가 아님"}, OCR 을 쓸 수 없으면 skipped 와 warnings 에 사유(파싱은 성공). 이미 스캔 쪽으로 OCR 한 쪽은 빠진다. deferred 모드여도 고른 쪽은 이 호출 안에서 OCR 한다.

    eprintln!("{}", sdp.version());          // 표준 출력에는 JSON 만 나가게 표준 오류로

    let mut results: Vec<Value> = vec![];
    for f in &files {
        results.push(match sdp.parse(f, None) {
            Ok(mut doc) => { doc["file"] = json!(f); doc }             // 라이브러리 결과 JSON 그대로
            Err(e) => json!({"file": f, "error": {"code": e.code, "message": e.msg}}),
        });
    }
    let all = if results.len() == 1 { results.remove(0) } else { Value::Array(results) };
    let text = serde_json::to_string_pretty(&all).unwrap();
    match out {
        Some(p) => std::fs::write(p, text).expect("결과 파일 쓰기 실패"),
        None => println!("{}", text),
    }
}   // sdp 가 사라질 때 sdp_close 가 불린다
