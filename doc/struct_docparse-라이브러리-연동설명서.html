struct_docparse 라이브러리를 언어별로 붙이는 법

문서(docx · pptx · xlsx · hwpx · doc · hwp · pdf · html · md · 그림 …)를 넣으면 블록 단위 글 + 라벨 (heading · paragraph · table · header · footer …)을 JSON 으로 돌려주는 라이브러리다. 함수는 C 모양(C ABI)이라 C 함수를 부를 수 있는 언어면 어디서든 쓸 수 있다. 이 문서는 Windows · 리눅스에서 Python · Rust · C/C++ · Java · PHP 등에 붙이는 법을 실제로 돌려 본 코드로 설명한다.

어느 언어든 흐름은 같다: ① 라이브러리 열기 → ② sdp_open(옵션) → ③ sdp_parse(파일) → ④ 결과 JSON 읽기 → ⑤ sdp_free → ⑥ sdp_close. 바인딩 파일은 이 흐름을 감싸 "열고 · 파싱하면 사전/Map 이 나오는" 모양으로 만들어 둔 것이다.

3모든 언어에 공통인 규칙

3-1. lib/ 폴더는 통째로 — 라이브러리가 "자기 옆"을 본다

라이브러리는 pdfium · onnxruntime · OCR 모델을 자기 파일이 있는 폴더에서 먼저 찾는다(그다음 실행 파일 옆). 그래서 lib/ 안 파일을 흩어 놓지 말고 폴더째 두면 된다. 다른 곳에 두었다면 열 때 옵션으로 알려 준다:

json
{"runtime": {"pdfium": "/opt/x/libpdfium.so", "onnxruntime": "/opt/x/libonnxruntime.so"},
 "ocr": {"model_dir": "/opt/x/models/ocr"}}
Windows 에서 다른 버전 onnxruntime.dll(예: 시스템 폴더의 1.17)이 먼저 잡히면 OCR 이 실패한다. 묶음의 onnxruntime 을 lib\ 에 그대로 두면 그것을 쓴다. 같은 프로그램이 이미 다른 onnxruntime 을 쓰고 있다면(환경변수 ORT_DYLIB_PATH) 그 값을 따른다 — 이 라이브러리는 ort 2.0.0-rc.10 이라 1.22 이상이어야 한다(1.22 미만은 거절, 더 새것은 경고만 — SimpleRAG Windows 배포본은 1.29).

3-2. 문자열은 전부 UTF-8 (끝에 0)

  • 경로 · 옵션 JSON · 결과 · 오류문 모두 UTF-8.
  • Windows C/C++ 주의: main(argc, argv) 의 argv 는 시스템 코드 페이지(한국어 Windows 는 CP949)라 한글 경로를 그대로 넘기면 -1("UTF-8 이 아닙니다")이 난다. GetCommandLineW + WideCharToMultiByte(CP_UTF8, …) 로 바꿔 넘긴다(6장 예제에 들어 있음).
  • Java(JNA)는 String 을 운영체제 기본 인코딩으로 바꾸므로, 바인딩은 byte[](UTF-8 + 0)로 넘긴다.

3-3. 받은 문자열은 sdp_free 로 돌려준다

char** out 으로 받은 결과는 라이브러리가 할당한 것이라 반드시 sdp_free(out). 언어 쪽 free 를 쓰면 안 된다. 예외: sdp_version() · sdp_last_error() 가 돌려준 글은 해제하지 않는다(라이브러리가 쥐고 있음).

3-4. 반환 코드

코드이름뜻
0SDP_OK성공 (평문 폴백으로 읽은 것도 0 — 결과의 format: "legacy")
-1SDP_EINVAL널 포인터 · 잘못된 JSON · 모르는 옵션 · UTF-8 아닌 글
-2SDP_EIO파일 없음 · 열 수 없음
-3SDP_EPARSE구조 파서와 평문 추출이 모두 실패(깨진 파일, OCR 끈 스캔 PDF 등)
-4SDP_EUNSUPPORTED지원 안 하는 형식, OCR 끈 상태의 그림 파일
-5SDP_EOCROCR 을 쓸 수 없거나 OCR 중 실패
-7SDP_ERUNTIMEpdfium 적재 실패(PDF 속성 · 쪽 글 함수)
-99SDP_EPANIC라이브러리 안 오류를 잡음 — 프로그램은 살아 있다

0 이 아니면 sdp_last_error() 로 사유를 읽는다(그 스레드의 마지막 오류).

3-5. 열 때 옵션 JSON — 빠진 키는 기본값

json
{
  "ocr": {
    "enabled": true,          // 기본 true — OCR 켬/끔
    "images": true,           // 그림 파일(.png .jpg .tif .bmp)도 OCR
    "mode": "inline",         // inline = 파싱 중 바로 OCR / deferred = 캐시만 보고 남은 쪽은 ocr.pending 으로
    "model_dir": "…",         // 기본: 라이브러리 옆 models/ocr
    "cache_dir": "…",         // OCR 결과 캐시 폴더(없으면 프로세스 메모리)
    "threads": 4, "max_pages": 100
  },
  "pdf": {"tables": true, "infer_headings": false},
  "runtime": {"pdfium": "…", "onnxruntime": "…"},
  "log": {"level": "warn"}    // warn | info | off
}

실제 JSON 에는 주석(//)을 넣으면 안 된다. 모르는 키는 -1 로 거절한다(오타를 조용히 넘기지 않게).

3-6. OCR 켜기·끄기 세 단계

  1. 열 때 — {"ocr":{"enabled":false}}
  2. 실행 중 — sdp_set_option(h, "ocr.enabled", "false") (끄면 OCR 엔진도 내려 메모리를 돌려준다)
  3. 호출마다 — sdp_parse(h, path, "{\"ocr\":{\"enabled\":false}}", &out)

모델 파일이 없으면 켜 놓아도 꺼진 것처럼 동작하고, sdp_get_status 의 ocr.reason 이 "models_missing" 이다.

3-7. 결과 JSON

json
{
  "schema": 1, "blocks_version": 5, "parser": "struct_docparse 0.1.0",
  "format": "docx", "title": "보고서_예시", "pages": null, "warnings": [], "raw_text": null,
  "ocr": {"enabled": true, "reason": null, "pending": [], "done": [], "whole": false},
  "blocks": [
    {"type": "heading", "text": "문서 파서 시험용 보고서", "level": 1},
    {"type": "heading", "text": "1. 개요", "level": 2},
    {"type": "paragraph", "text": "이 문서는 구조화 문서 파서를 시험하려고 지어낸 예시 문서다."},
    {"type": "table", "text": "| 항목 | 금액 |…", "rows": [["항목","금액"],["…","…"]], "header_rows": 1, "page": 2},
    {"type": "paragraph", "text": "그림에서 읽은 글", "page": 3, "source": "ocr"}
  ]
}
라벨 type뜻라벨 type뜻
heading제목 · 절 (level 1~9)header쪽 머리글(반복)
paragraph본문 문단footer쪽 꼬리글
list_item목록 (level = 깊이)page_number쪽 번호
table표 (rows · header_rows)toc목차
caption그림 · 표 설명note각주 · 슬라이드 노트
code코드 조각

format: "legacy"(hwp · ppt · xls · txt · csv 등)는 블록 없이 raw_text 에 평문이 온다. 블록이 없을 때 raw_text 를 보면 된다.

3-8. 스레드 · 핸들 · 판

  • 핸들 하나를 여러 스레드가 같이 써도 된다(PDF · OCR 은 안에서 차례를 지킨다).
  • 옵션은 프로세스에 한 벌 — 핸들을 여럿 열면 마지막에 연 옵션을 함께 쓴다.
  • 열자마자 sdp_abi_version() == 1 인지 확인한다(함수 모양이 바뀌면 이 숫자가 바뀐다).
  • blocks_version 이 바뀌면 결과 모양이 달라진 것 — 저장해 둔 결과를 다시 만들지 판단할 때 쓴다.

4Python

표준 라이브러리 ctypes 만 쓴다. bindings/python/struct_docparse.py 를 프로젝트에 복사하거나 경로에 더한다.

python
from struct_docparse import DocParser, DocParseError

with DocParser("lib/libstruct_docparse.so",            # Windows: r"lib\struct_docparse.dll"
               {"ocr": {"enabled": True, "mode": "inline"}}) as p:
    print(p.version(), p.status()["ocr"]["enabled"])
    doc = p.parse("보고서.hwpx")                         # dict
    for b in doc["blocks"]:
        print(b["type"], b.get("level", ""), b["text"][:40])
    try:
        p.parse("스캔.jpg", ocr=False)                   # 이번 호출만 OCR 끔
    except DocParseError as e:
        print(e.code, e.msg)                             # -4 그림 파일은 OCR 이 켜져 있어야 …

5Rust

빌드할 때 라이브러리가 없어도 되도록 실행 중에 여는 방식(libloading)이다. bindings/rust/struct_docparse.rs 를 복사하고 의존성을 더한다.

toml
[dependencies]
libloading = "0.8"
serde_json = "1"
rust
mod struct_docparse;
use struct_docparse::StructDocParse;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let sdp = StructDocParse::open("lib/libstruct_docparse.so", r#"{"ocr":{"mode":"inline"}}"#)?;
    println!("{}", sdp.version());
    let doc = sdp.parse("보고서.hwpx", None)?;                       // serde_json::Value
    for b in doc["blocks"].as_array().unwrap() {
        println!("[{}] {}", b["type"], b["text"].as_str().unwrap_or(""));
    }
    match sdp.parse("스캔.jpg", Some(r#"{"ocr":{"enabled":false}}"#)) {
        Err(e) if e.code == -4 => println!("OCR 끔이라 그림 거절"),
        other => println!("{:?}", other.map(|d| d["format"].clone())),
    }
    Ok(())   // sdp 가 사라질 때 sdp_close
}
bash
cd examples/rust
cargo run --release -- ../../tests/samples/보고서_예시.docx ../../tests/samples/스캔_예시.jpg

메서드: open · version · status · parse(path, call_opts) · extract_text · set_option · pdf_info (Drop 에서 닫힘). Rust 프로젝트라면 이 저장소의 sdp-core crate 를 직접 의존해 DLL 없이 쓸 수도 있다(sdp_core::api::parse).

6C / C++

6-1. Windows (MSVC)

"x64 Native Tools 명령 프롬프트"에서(또는 examples\c\build_win.cmd):

cmd

실행할 때는 example.exe 를 lib\ 에 두거나, lib\ 를 PATH 에 넣는다(struct_docparse.dll 을 찾아야 하므로).

6-2. 리눅스 (gcc)

bash
gcc -std=c99 -I include examples/c/example.c -L lib -lstruct_docparse -Wl,-rpath,'$ORIGIN/lib' -o example
./example 문서.hwpx

-Wl,-rpath,'$ORIGIN/…' 는 "실행 파일 기준 상대 위치에서 .so 를 찾아라" 라는 뜻이다. 넣지 않으면 LD_LIBRARY_PATH=lib 를 줘야 한다.

6-3. 코드

c
#include <stdio.h>
#include "struct_docparse.h"

int main(void)
{
    SdpHandle* h = NULL;
    char* out = NULL;
    if (sdp_abi_version() != 1) return 1;
    if (sdp_open("{\"ocr\":{\"mode\":\"inline\"}}", NULL, NULL, &h) != SDP_OK) {
        fprintf(stderr, "%s\n", sdp_last_error());
        return 1;
    }
    /* 경로는 UTF-8 — Windows 에서 argv 를 넘길 땐 example.c 의 utf8_argv 처럼 바꾼다 */
    int rc = sdp_parse(h, "보고서.hwpx", NULL, &out);
    if (rc == SDP_OK) {
        puts(out);          /* JSON — cJSON · jansson · nlohmann::json 등으로 읽는다 */
        sdp_free(out);      /* 반드시 sdp_free */
    } else {
        fprintf(stderr, "실패(%d) %s\n", rc, sdp_last_error());
    }
    sdp_close(h);
    return 0;
}

6-4. 링크 없이 실행 중에 열기 (선택)

7Java

JNA 5.x 를 쓴다(Java 8 이상). 묶음의 bindings/java/structdocparse/(StructDocParse.java · 작은 JSON 해석기 Json.java)를 소스에 넣는다. Maven 이면 net.java.dev.jna:jna:5.14.0.

java
import structdocparse.StructDocParse;
import java.util.*;

try (StructDocParse sdp = StructDocParse.load("lib/libstruct_docparse.so", "{\"ocr\":{\"mode\":\"inline\"}}")) {
    System.out.println(sdp.version());
    Map<String, Object> doc = sdp.parse("보고서.hwpx", null);
    for (Object o : (List<?>) doc.get("blocks")) {
        Map<?, ?> b = (Map<?, ?>) o;
        System.out.println("[" + b.get("type") + "] " + b.get("text"));
    }
    try {
        sdp.parse("스캔.jpg", "{\"ocr\":{\"enabled\":false}}");
    } catch (StructDocParse.SdpException e) {
        System.out.println(e.code + " " + e.getMessage());   // -4
    }
}

8PHP 미시험

PHP 7.4+ 의 FFI 확장을 쓴다. php.ini 에 extension=ffi, 웹 서버(FPM)에서는 ffi.enable=true 도 필요하다. 시험 PC · 빌드서버에 PHP 가 없어 이 코드는 아직 돌려 보지 않았다 — 다른 언어와 같은 함수를 같은 방식으로 부르므로 그대로 될 것으로 보지만, 처음 쓸 때 예제로 확인한다.

php
<?php
require 'bindings/php/StructDocParse.php';

$sdp = StructDocParse::load('/opt/sdp/lib/libstruct_docparse.so', ['ocr' => ['mode' => 'inline']]);
echo $sdp->version(), "\n";
$doc = $sdp->parse('보고서.hwpx');                       // 연관 배열
foreach ($doc['blocks'] as $b) {
    echo "[{$b['type']}] {$b['text']}\n";
}
try {
    $sdp->parse('스캔.jpg', ['ocr' => ['enabled' => false]]);
} catch (StructDocParseException $e) {
    echo $e->getCode(), ' ', $e->getMessage(), "\n";     // -4
}
$sdp->close();

10리눅스에서 쓰기

10-1. 어떤 리눅스에서 도나

부분필요한 glibc되는 배포판(예)
libstruct_docparse.so · libpdfium.so (문서 파싱 전부)2.15 이상CentOS 7 · RHEL 7 이상, Ubuntu 14.04 이상 — 사실상 모든 현역 리눅스
libonnxruntime.so 1.22 (OCR 만)2.27 이상RHEL/Rocky/Alma 8 이상, Ubuntu 18.04 이상, Debian 10 이상
CentOS 7 (glibc 2.17) 에서는 문서 파싱은 되지만 OCR 은 안 된다. 스캔 PDF · 그림을 넣으면 -5("onnxruntime … 적재할 수 없습니다")가 나고 프로그램은 계속 돈다. OCR 이 필요하면 ① glibc 2.27 이상 서버를 쓰거나 ② rockylinux:8 같은 컨테이너 안에서 돌린다(빌드서버 시험이 이 방식). OCR 을 아예 안 쓸 거면 {"ocr":{"enabled":false}} 로 열면 깔끔하다.

확인 명령:

bash
ldd --version | head -1                      # 서버 glibc
objdump -T lib/libstruct_docparse.so | grep -o 'GLIBC_[0-9.]*' | sort -uV | tail -1   # 요구 glibc
ldd lib/libstruct_docparse.so                # 빠진 공유 라이브러리가 없는지

Windows PC 에서 scripts/linux-build.sh 한 번이면 빌드서버(CentOS 7)에서 빌드 · 단위 시험 · 예제 시험 · Windows 결과와 비교 · 묶기까지 한다.

bash

  • 접속 정보: scripts/server.env(git 에 안 올라감, server.env.sample 참고) → 접속 정보 파일 경로 · 빌드 폴더 · cargo 위치.

11문제가 생기면

증상원인해결

그림 · 스캔 PDF 가 -5onnxruntime 버전이 다름 / glibc 2.27 미만 / 모델 없음sdp_get_status 의 ocr.reason · 오류문 확인, 10-1 참고
그림이 -4OCR 이 꺼져 있음정상 동작. OCR 을 켠다
PDF 가 -3 이고 사유에 "pdfium … 적재 실패"pdfium 이 옆에 없음lib/ 를 통째로 두거나 runtime.pdfium 옵션
메모리가 계속 늘어 보임OCR 엔진이 올라가 있음OCR 을 다 쓴 뒤 sdp_ocr_unload
프로그램이 죽지는 않는데 -99라이브러리 안 오류그 파일을 보내 주면 고친다(다른 파일은 계속 처리된다)
