struct_docparse 라이브러리를 언어별로 붙이는 법

문서(docx · pptx · xlsx · hwpx · doc · hwp · pdf · html · md · 그림 …)를 넣으면 블록 단위 글 + 라벨 (heading · paragraph · table · header · footer …)을 JSON 으로 돌려주는 라이브러리다. 함수는 C 모양(C ABI)이라 C 함수를 부를 수 있는 언어면 어디서든 쓸 수 있다. 이 문서는 Windows · 리눅스에서 Python · Rust · C/C++ · Java · PHP 등에 붙이는 법을 실제로 돌려 본 코드로 설명한다.

3모든 언어에 공통인 규칙

3-1. lib/ 폴더는 통째로 — 라이브러리가 "자기 옆"을 본다

라이브러리는 pdfium · onnxruntime · OCR 모델을 자기 파일이 있는 폴더에서 먼저 찾는다(그다음 실행 파일 옆). 그래서 lib/ 안 파일을 흩어 놓지 말고 폴더째 두면 된다. 다른 곳에 두었다면 열 때 옵션으로 알려 준다:

json
{"runtime": {"pdfium": "/opt/x/libpdfium.so", "onnxruntime": "/opt/x/libonnxruntime.so"},
 "ocr": {"model_dir": "/opt/x/models/ocr"}}
Windows 에서 다른 버전 onnxruntime.dll(예: 시스템 폴더의 1.17)이 먼저 잡히면 OCR 이 실패한다. 묶음의 onnxruntime 을 lib\ 에 그대로 두면 그것을 쓴다. 같은 프로그램이 이미 다른 onnxruntime 을 쓰고 있다면(환경변수 ORT_DYLIB_PATH) 그 값을 따른다 — 이 라이브러리는 ort 2.0.0-rc.10 이라 1.22 이상이어야 한다(1.22 미만은 거절, 더 새것은 경고만 — SimpleRAG Windows 배포본은 1.29).

3-2. 문자열은 전부 UTF-8 (끝에 0)

  • 경로 · 옵션 JSON · 결과 · 오류문 모두 UTF-8.
  • Windows C/C++ 주의: main(argc, argv) 의 argv 는 시스템 코드 페이지(한국어 Windows 는 CP949)라 한글 경로를 그대로 넘기면 -1("UTF-8 이 아닙니다")이 난다. GetCommandLineW + WideCharToMultiByte(CP_UTF8, …) 로 바꿔 넘긴다(6장 예제에 들어 있음).
  • Java(JNA)는 String 을 운영체제 기본 인코딩으로 바꾸므로, 바인딩은 byte[](UTF-8 + 0)로 넘긴다.

3-3. 받은 문자열은 sdp_free 로 돌려준다

char** out 으로 받은 결과는 라이브러리가 할당한 것이라 반드시 sdp_free(out). 언어 쪽 free 를 쓰면 안 된다. 예외: sdp_version() · sdp_last_error() 가 돌려준 글은 해제하지 않는다(라이브러리가 쥐고 있음).

3-4. 반환 코드

코드이름뜻
0SDP_OK성공 (평문 폴백으로 읽은 것도 0 — 결과의 format: "legacy")
-1SDP_EINVAL널 포인터 · 잘못된 JSON · 모르는 옵션 · UTF-8 아닌 글
-2SDP_EIO파일 없음 · 열 수 없음
-3SDP_EPARSE구조 파서와 평문 추출이 모두 실패(깨진 파일, OCR 끈 스캔 PDF 등)
-4SDP_EUNSUPPORTED지원 안 하는 형식, OCR 끈 상태의 그림 파일
-5SDP_EOCROCR 을 쓸 수 없거나 OCR 중 실패
-7SDP_ERUNTIMEpdfium 적재 실패(PDF 속성 · 쪽 글 함수)
-99SDP_EPANIC라이브러리 안 오류를 잡음 — 프로그램은 살아 있다

0 이 아니면 sdp_last_error() 로 사유를 읽는다(그 스레드의 마지막 오류).

3-5. 열 때 옵션 JSON — 빠진 키는 기본값

json
{
  "ocr": {
    "enabled": true,          // 기본 true — OCR 켬/끔
    "images": true,           // 그림 파일(.png .jpg .tif .bmp)도 OCR
    "mode": "inline",         // inline = 파싱 중 바로 OCR / deferred = 캐시만 보고 남은 쪽은 ocr.pending 으로
    "model_dir": "…",         // 기본: 라이브러리 옆 models/ocr
    "cache_dir": "…",         // OCR 결과 캐시 폴더(없으면 프로세스 메모리)
    "threads": 4, "max_pages": 100,
    "layout": true,           // OCR 줄 구조 분석(다단 · 문단 · 제목 · 목록 · 머리말) — 끄면 화면 한 줄이 문단 하나
    "arena": true,            // 0.1.1~ OCR 메모리 아레나 켬 + 실행마다 줄이기(인식이 빨라짐) — false 면 0.1.0 과 같은 방식
    "page_cap": "a4",         // 0.1.1~ A4 보다 큰 PDF 쪽 · 그림을 A4 크기로 줄여 OCR — "none" 이면 원래 크기
    "image_cap": false,       // 0.1.1~ 그림 파일에도 page_cap 을 쓰나(기본 끔 — 4K 화면 캡처 작은 글자가 나빠짐)
    "page_up": true,          // 0.1.1~ A4 보다 작은 PDF 쪽(A5 · A6 등)을 최대 1.4배 해상도로 그려 OCR — false 면 200dpi 그대로
    "orient": true,           // 0.1.1~ 누운 · 뒤집힌 스캔 쪽을 바로 세워 OCR(쪽 방향 보정) — false 면 이전과 같음
    "orient_flip": false      // 0.1.1~ 바로 선 쪽도 뒤집힘(180°)을 확인 — 기본 끔(누운 쪽만 판별). 켜면 바로 선 쪽마다 0.02~0.31초가 붙는다
  },
  "pdf": {"tables": true, "infer_headings": false},
  "runtime": {"pdfium": "…", "onnxruntime": "…"},
  "log": {"level": "warn"},   // warn | info | off
  "extra_text": true,         // 0.2.0~ 본문 밖 글(PDF 글상자 · 서식 칸 · docx 메모 · SmartArt) 읽기 — false 면 0.1.x 와 같은 본문
  "chunk": {                  // 0.3.0~ 청킹 기본값 — 여기 적어도 켜지지는 않는다. 켜는 것은 호출마다(3-9)
    "tokenizer": "…/tokenizer.json",  // e5 토크나이저 파일. unit 이 tokens 면 필요
    "unit": "tokens",         // tokens = 토큰 수로 잼 / chars = 글자 수로 잼(아래 크기 값이 모두 글자 수 뜻)
    "mode": "structured",     // structured = 절 단위 / fixed = 고정 크기
    "tokens": 128, "overlap": 16, "min_tokens": 16,
    "table_header_max_tokens": 64, "table_whole": 384,
    "overflow_ratio": 1.0, "sentence_split": false, "hard_max": 510,
    "prefix": true, "prefix_max_chars": 80
  }
}

실제 JSON 에는 주석(//)을 넣으면 안 된다. 모르는 키는 -1 로 거절한다(오타를 조용히 넘기지 않게). 그래서 arena · page_cap · image_cap · page_up · orient · orient_flip 을 0.1.0 라이브러리에 넘기면 열기가 실패한다 — 라이브러리와 함께 올린다. 쪽 방향 보정으로 돌려 읽은 쪽은 OCR 캐시에 rot(시계 방향 각도)이 함께 남고, 줄 좌표는 바로 선 쪽 기준이다. 자세한 근거는 plan/OCR쪽방향보정_설계서_20261117.html. 세 옵션은 sdp_set_option 으로 바꿔도 된다(아레나를 바꾸면 다음 OCR 때 엔진을 다시 만든다). 자세한 근거는 plan/OCR속도개선_설계서_20261117.html.

extra_text(0.2.0~, 기본 켬)는 사이냅이 읽는 본문 밖 글을 함께 읽는다 — PDF 글상자 주석(숨긴 것도) · PDF 서식 칸 값 · docx 메모 · pptx/docx SmartArt. 이 블록은 source 가 "extra" 다. OCR 하는 스캔 쪽은 보이는 주석을 OCR 이 읽으므로 숨긴 주석만 글로 붙는다. 실행 중에는 sdp_set_option(h, "extra_text", "false") 로 끈다(묶음 없는 맨 위 키). 0.1.x 라이브러리에 넘기면 모르는 키라 열기가 실패한다. 근거 · 사이냅 비교는 plan/본문밖글읽기_설계서_20261118.html.

3-6. OCR 켜기·끄기 세 단계

  1. 열 때 — {"ocr":{"enabled":false}}
  2. 실행 중 — sdp_set_option(h, "ocr.enabled", "false") (끄면 OCR 엔진도 내려 메모리를 돌려준다)
  3. 호출마다 — sdp_parse(h, path, "{\"ocr\":{\"enabled\":false}}", &out)

모델 파일이 없으면 켜 놓아도 꺼진 것처럼 동작하고, sdp_get_status 의 ocr.reason 이 "models_missing" 이다.

블록의 source — 없으면 파서가 읽은 글, "ocr" 은 OCR 글, "inferred" 는 글자 크기로 짐작한 제목, "extra" 는 본문 밖 글(0.2.0~).

format: "legacy"(hwp · ppt · xls · txt · csv 등)는 블록 없이 raw_text 에 평문이 온다. 블록이 없을 때 raw_text 를 보면 된다.

3-8. 스레드 · 핸들 · 판

  • 핸들 하나를 여러 스레드가 같이 써도 된다(PDF · OCR 은 안에서 차례를 지킨다).
  • 옵션은 프로세스에 한 벌 — 핸들을 여럿 열면 마지막에 연 옵션을 함께 쓴다.
  • 열자마자 sdp_abi_version() == 1 인지 확인한다(함수 모양이 바뀌면 이 숫자가 바뀐다).
  • blocks_version 이 바뀌면 결과 모양이 달라진 것 — 저장해 둔 결과를 다시 만들지 판단할 때 쓴다.
  • 청크를 저장해 쓰면 chunk_version(0.3.0~)도 함께 적어 두고, 둘 중 하나라도 바뀌면 다시 자른다.

3-9. 청크로 받기 — 블록 단위 청킹 0.3.0~

0.3.0 부터 쓸 수 있다. 0.2.x 라이브러리에 chunk 옵션을 넘기면 모르는 옵션이라 -1 이 나고, sdp_chunk 함수도 없다 — 라이브러리와 바인딩을 함께 올린다. 설계 · 시험: plan/블록청킹_DLL옵션_설계서_20261127.md.

블록을 받은 뒤 검색용으로 잘게 자르는 일(청킹)을 라이브러리가 대신 한다. SimpleRAG 가 쓰는 규칙 그대로다.

  1. 제목 블록의 수준으로 절을 나눈다(머리글 · 바닥글 · 쪽 번호 · 목차 블록은 뺀다).
  2. 작은 절은 크기(tokens) 안에서 이어 묶고, 큰 절은 제목 · 블록 · 표 행 단위로 자른다.
  3. 표는 행 경계에서 자르고 조각마다 머리글 행을 다시 붙인다. 작은 표(table_whole 이하)는 통째로 둔다.
  4. 청크 앞에 [문서 제목 > 절 > …] 접두를 붙이고, 청크가 실제로 시작하는 쪽을 찾아 적는다.
  5. 510 토큰(hard_max)을 넘는 청크는 다시 자르고, min_tokens 보다 짧은 청크는 버린다.

① 켜기 — 호출마다. 열 때 옵션(3-5)의 chunk 는 기본값일 뿐이고, sdp_parse 의 호출 옵션에 chunk 를 줄 때만 자른다. 호출 옵션 chunk 는 true(기본값으로 켬) · 객체(켬 + 이 호출만 덮어쓰기, "enabled": false 면 끔) · false(끔). tokens 만 바꾸고 overlap 을 주지 않으면 overlap = max(8, tokens/8) 로 따라간다(SimpleRAG 설정과 같은 규칙). 실행 중에 기본값을 바꾸려면 sdp_set_option(h, "chunk.tokens", "256"). overlap 이 tokens 이상이거나 hard_max 가 tokens 보다 작은 등 어긋난 값은 -1.

c
/* 열 때 — 토크나이저 경로와 기본 크기 */
sdp_open("{\"chunk\":{\"tokenizer\":\"models/e5-small-ko/tokenizer.json\"}}", NULL, NULL, &h);
/* 호출마다 — 켜기만 */
sdp_parse(h, path, "{\"chunk\":true}", &out);
/* 이 호출에서만 크기를 바꿔 */
sdp_parse(h, path, "{\"chunk\":{\"enabled\":true,\"tokens\":256}}", &out);

② 길이를 무엇으로 재나. 기본은 e5 토크나이저의 토큰 수다(tokenizer.json — SimpleRAG 의 models/e5-small-ko/tokenizer.json 과 같은 파일). 파일을 못 읽으면 열기가 아니라 첫 청킹 호출이 -1 로 실패한다 — 청킹을 안 쓰는 프로그램은 영향이 없다. 토크나이저가 없으면 "unit": "chars" 로 글자 수로 잴 수 있다. 이때는 tokens · overlap · hard_max 등 크기 값이 모두 글자 수 뜻이다. 토크나이저는 처음 청킹할 때 한 번 읽는다(17MB 파일 약 0.7초).

③ 결과. 청킹을 켠 호출에만 chunk_version · chunking · chunks 가 붙는다. blocks 는 청킹을 켜도 끄도 같다.

json
{

청크 필드뜻
text청크 글 — 접두 [문서 > 절] 포함. 임베딩 · 검색 · LLM 에 그대로 넣는 글
tokensunit 기준 길이(토큰 수 또는 글자 수)
section_id · path첫 절 번호(문서 안 0부터) · 제목 경로. 평문(legacy) · 고정 크기는 null · []
source첫 절 제목의 출처(parser · inferred · regex · ocr · extra). 평문은 "legacy", 고정 크기는 ""
page · page_from · page_to청크가 시작하는 쪽 · 걸친 쪽 범위(1부터). 시작 쪽을 못 찾으면 page 만 null
  • 평문 형식(hwp · txt 등, format: "legacy")도 자른다 — 조문 · 번호 절을 스스로 찾아 절로 나눈다.
  • 청크가 0개여도 오류가 아니다("chunks": []).
  • OCR 을 deferred 로 쓰면 아직 OCR 안 한 쪽의 글은 청크에 없다. OCR 뒤 다시 sdp_parse 하면 새 청크가 나온다.

④ 다시 자르기 — sdp_chunk. 저장해 둔 sdp_parse 결과(블록)로 파싱 · OCR 없이 크기만 바꿔 다시 자른다.

c
int32_t sdp_chunk(SdpHandle* h, const char* doc_json, const char* chunk_opts_json, char** out_json);
/* doc_json = sdp_parse 결과 그대로, chunk_opts_json = {"tokens":256} 처럼(NULL 이면 열 때 기본값)
   out = {"chunk_version":1, "chunking":{…}, "chunks":[…]} */

⑤ 지원 확인. sdp_version() 에 chunk= 가 있으면 된다(예: "0.3.0 blocks=7 chunk=1 ocr=…"). 함수를 더하기만 해서 sdp_abi_version() 은 1 그대로다. sdp_get_status 의 chunk 에 기본값 · 토크나이저 경로 · 읽어 둔 토크나이저가 나온다.

mod struct_docparse;
use struct_docparse::StructDocParse;
use serde_json::{json, Value};

fn main() {
    // 명령줄: 문서 경로들 + 선택 --out <파일>
    let (mut files, mut out) = (vec![], None);
    let mut args = std::env::args().skip(1);
    while let Some(a) = args.next() {
        if a == "--out" { out = args.next(); } else { files.push(a); }
    }

    // lib 폴더의 DLL 을 연다 — 리눅스는 "lib/libstruct_docparse.so"
    let dll = concat!(env!("CARGO_MANIFEST_DIR"), r"\lib\struct_docparse.dll");
    let sdp = StructDocParse::open(dll, r#"{"ocr":{"enabled":true,"mode":"inline"}}"#)
        .expect("struct_docparse 열기 실패");
    eprintln!("{}", sdp.version());          // 표준 출력에는 JSON 만 나가게 표준 오류로

    let mut results: Vec<Value> = vec![];
    for f in &files {
        results.push(match sdp.parse(f, None) {
            Ok(mut doc) => { doc["file"] = json!(f); doc }             // 라이브러리 결과 JSON 그대로
            Err(e) => json!({"file": f, "error": {"code": e.code, "message": e.msg}}),
        });
    }
    let all = if results.len() == 1 { results.remove(0) } else { Value::Array(results) };
    let text = serde_json::to_string_pretty(&all).unwrap();
    match out {
        Some(p) => std::fs::write(p, text).expect("결과 파일 쓰기 실패"),
        None => println!("{}", text),
    }
}   // sdp 가 사라질 때 sdp_close 가 불린다

5-4. 결과 읽기 — blocks 와 raw_text

라이브러리는 결과를 JSON 문자열로 돌려주고, 바인딩이 그것을 serde_json::Value 로 풀어 준다(모양은 3-7). 형식에 따라 본문이 들어가는 칸이 다르다.

형식format본문 자리
docx · hwpx · pptx · xlsx · pdf · html · md · 그림그 형식 이름blocks — 블록마다 type · text · page · source
hwp(한글 5.0) · doc 일부 · ppt · xls · txt · csv 등"legacy"raw_text — 평문 하나. blocks 는 빈 배열이다(실패가 아니다)

let doc = sdp.parse(path, None)?;
let blocks = doc["blocks"].as_array().cloned().unwrap_or_default();
if blocks.is_empty() {
    // legacy 형식 — 평문이 raw_text 에 온다
    println!("{}", doc["raw_text"].as_str().unwrap_or(""));
} else {
    for b in &blocks {
        println!("[{}] {}", b["type"].as_str().unwrap_or(""), b["text"].as_str().unwrap_or(""));
    }
}

호출마다 옵션: sdp.parse(path, Some(r#"{"ocr":{"enabled":false}}"#)) — 이번 호출만 OCR 끔(그림 파일이면 -4 가 정상).

5-6. 메서드

메서드돌려주는 것
StructDocParse::open(dll_경로, 옵션_json)Result<StructDocParse, SdpError> — 옵션은 3-5

#include <stdio.h>
#include "struct_docparse.h"

int main(void)
{
    SdpHandle* h = NULL;
    char* out = NULL;
    if (sdp_abi_version() != 1) return 1;
    if (sdp_open("{\"ocr\":{\"mode\":\"inline\"}}", NULL, NULL, &h) != SDP_OK) {
        fprintf(stderr, "%s\n", sdp_last_error());
        return 1;
    }
    /* 경로는 UTF-8 — Windows 에서 argv 를 넘길 땐 example.c 의 utf8_argv 처럼 바꾼다 */
    int rc = sdp_parse(h, "보고서.hwpx", NULL, &out);
    if (rc == SDP_OK) {
        puts(out);          /* JSON — cJSON · jansson · nlohmann::json 등으로 읽는다 */
        sdp_free(out);      /* 반드시 sdp_free */
    } else {
        fprintf(stderr, "실패(%d) %s\n", rc, sdp_last_error());
    }
    sdp_close(h);
    return 0;
}

10리눅스에서 쓰기

10-1. 어떤 리눅스에서 도나

부분필요한 glibc되는 배포판(예)
libstruct_docparse.so · libpdfium.so (문서 파싱 전부)2.15 이상CentOS 7 · RHEL 7 이상, Ubuntu 14.04 이상 — 사실상 모든 현역 리눅스
libonnxruntime.so 1.22 (OCR 만)2.27 이상RHEL/Rocky/Alma 8 이상, Ubuntu 18.04 이상, Debian 10 이상
0.3.0 부터 문서 파싱 쪽 요구 glibc 가 2.15 → 2.17 로 오른다 — 청킹용 토크나이저(tokenizers)를 넣은 결과다(2026-11-27 시험 빌드). CentOS 7 / RHEL 7(2.17) 이상은 그대로 돈다. 2.15 · 2.16(Ubuntu 12.04 등)만 빠진다.
CentOS 7 (glibc 2.17) 에서는 문서 파싱은 되지만 OCR 은 안 된다. 스캔 PDF · 그림을 넣으면 -5("onnxruntime … 적재할 수 없습니다")가 나고 프로그램은 계속 돈다. OCR 이 필요하면 ① glibc 2.27 이상 서버를 쓰거나 ② rockylinux:8 같은 컨테이너 안에서 돌린다(빌드서버 시험이 이 방식). OCR 을 아예 안 쓸 거면 {"ocr":{"enabled":false}} 로 열면 깔끔하다.
