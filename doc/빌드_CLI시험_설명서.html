Struct-DocParse-OCR · 사용 안내 · 2026-11-16 · DLL 0.1.0 (ABI 1)

문서 파서 DLL 빌드하고 CLI 로 시험하기

이 저장소는 문서(docx · pptx · hwpx · pdf …)를 읽어 글 + 라벨(제목 · 문단 · 표 · 머리글 …)로 돌려주는 DLL 을 만든다. 이 안내를 위에서부터 따라 하면 DLL 을 빌드하고, 함께 만들어지는 시험 프로그램 sdp.exe 로 문서를 직접 넣어 결과를 볼 수 있다. 명령은 모두 PowerShell 기준이고, 저장소 폴더 D:\Project\Struct-DocParse-OCR-rust 에서 실행한다.

이름 주의 — DLL 파일 이름은 struct_docparse.dll 이다(하이픈 - 이 아니라 밑줄 _). Rust 는 DLL 이름에 하이픈을 쓰지 않는다.

DLL(struct_docparse.dll)은 다른 프로그램이 불러 쓰는 부품이라 혼자서는 실행되지 않는다. 그래서 같은 코드를 쓰는 시험 프로그램 sdp.exe 를 함께 빌드한다. sdp.exe 는 DLL 과 똑같은 함수(C ABI)를 거쳐 문서를 읽으므로, sdp.exe 로 본 결과가 곧 DLL 의 결과다.

4실행 파일 옆에 둘 것

DLL 은 자기 옆 폴더에서 pdfium.dll · onnxruntime.dll · models\ocr\ 를 찾는다. 그래서 빌드 결과 폴더(target\release)에 아래처럼 복사해 둔다. 처음 한 번만 하면 된다.

target\release\ ├─ struct_docparse.dll ← 빌드 결과 ├─ sdp.exe ← 빌드 결과 ├─ pdfium.dll ← 복사 ├─ onnxruntime.dll ← 복사 (OCR 용) ├─ onnxruntime_providers_shared.dll └─ models\ocr\ ← 복사 (OCR 모델 3개) ├─ PP-OCRv6_tiny_det.onnx ├─ korean_PP-OCRv5_mobile_rec.onnx └─ korean_PP-OCRv5_mobile_rec.dict.txt

런타임 DLL 은 저장소의 third_party\, OCR 모델은 models\ocr\ 에서 복사한다(세 줄을 차례로):

Copy-Item .\third_party\pdfium\windows-x64\pdfium.dll, .\third_party\onnxruntime\windows-x64\*.dll .\target\release\
New-Item -ItemType Directory -Force .\target\release\models\ocr | Out-Null
Copy-Item .\models\ocr\* .\target\release\models\ocr\
onnxruntime 은 1.22 이상 — Windows 시스템 폴더 등에 오래된 버전(예: 1.17)이 있으면 그것을 집어 OCR 이 실패한다. 위처럼 DLL 옆에 맞는 버전을 두면 그것을 먼저 쓴다.

모델을 다른 곳에 두었다면 복사 대신 --ocr-dir 폴더 옵션이나 환경변수 SDP_OCR_DIR 로 알려 줄 수 있다.

[sdp] ⚠️ OCR 모델 파일 없음: …\target\release\models\ocr\PP-OCRv6_tiny_det.onnx — 스캔 문서 OCR 을 건너뜁니다

OCR 만 따로 보기 (ocrfile)

블록으로 정리하기 전의 OCR 결과(줄 · 점수 · 상자 좌표 · 걸린 시간)를 본다. 캐시는 쓰지 않는다. --pages 로 쪽을 고를 수 있다(예: 1,3-5).

.\target\release\sdp.exe ocrfile .\tests\samples\스캔_예시.pdf --pages 1
화면 — 쪽마다 앞 5줄
── 1쪽 · OCR 1521ms · 상자 15
  스캔시험문서
  이 쪽은 글자층이 없는 그림이다.
  OCR 로 읽어야 글이 나온다.
  항목 값 비고
  형식 docx 시험

줄마다 상자 좌표까지 보려면 --out 파일.json 을 붙인다. 그림 폴더를 넣으면 안의 그림을 이름 순으로 모두 읽는다.

9여러 문서 한꺼번에 (dump · compare)

① 목록 파일 만들기

메모장으로 한 줄에 문서 경로 하나씩 적어 .txt 로 저장한다(UTF-8). 예: work\mini.txt

tests/samples/스캔_예시.png
tests/samples/글자층_예시.pdf

상대 경로는 sdp.exe 를 실행한 폴더 기준이다. 저장소에는 시험 문서 10건 목록 tests\samples.txt 가 이미 있다. 실제 업무 문서로 시험하려면 tests\private\(git 에 올라가지 않음)에 문서와 목록을 두고 쓴다.

② dump — 문서마다 결과 JSON 저장

.\target\release\sdp.exe dump .\work\mini.txt .\work\out_a
화면 — 문서마다 걸린 시간
[1/2] 1270ms 스캔_예시.png
[2/2] 40ms 글자층_예시.pdf
끝 — 2건 1.3초
work\out_a\ ├─ index.json ← 번호 ↔ 원래 경로 · 성공(rc 0)/실패 · 걸린 ms ├─ 0000\스캔_예시.png.blocks.json ← 목록 첫 줄의 결과 └─ 0001\글자층_예시.pdf.blocks.json
실패한 문서는 JSON 이 만들어지지 않는다. index.json 에서 "rc" 가 0 이 아닌 줄과 "err"(사유)를 확인한다.

③ compare — 두 결과 비교

코드를 고친 뒤 결과가 달라졌는지 볼 때 쓴다. 예를 들어 OCR 끔으로 한 번 더 뽑아 비교해 보면:

.\target\release\sdp.exe dump .\work\mini.txt .\work\out_b --no-ocr
.\target\release\sdp.exe compare .\work\out_a .\work\out_b
화면 — 무엇이 어디서 달라졌는지 첫 차이를 보여 준다
없음  0000 스캔_예시.png.blocks.json
다름  0001 글자층_예시.pdf.blocks.json — .ocr.enabled: true ≠ false
같음 0 · 다름 1 · 새 쪽에 없음 1 (기준 2건)
  • 첫 번째 폴더가 기준이고, 기준 JSON 에 있는 필드만 비교한다.
  • 없음 = 기준에는 있는데 새 쪽에는 결과가 없음(여기서는 OCR 을 꺼서 그림을 못 읽음).
  • 모두 같으면 같음 N · 다름 0 · 새 쪽에 없음 0 이 나오고 종료 코드 0, 아니면 1.
분리 전 SimpleRAG 와 같은지 보는 법 — tools\baseline.py 로 옛 SimpleRAG exe 의 결과를 기준 폴더로 만들고, sdp.exe dump … --mode deferred 결과와 compare 한다(README 의 "같음 검증"). 2026-11-16 에 실제 문서 84건(공개 저장소에는 없음) 모두 같았다.

10OCR 캐시 채우기 (ocr)

OCR 은 느리므로, 한 번 읽은 결과를 캐시 폴더에 저장해 두고 다음부터는 바로 쓸 수 있다. SimpleRAG 가 이렇게 쓴다(먼저 글자층만 색인 → 쉬는 동안 OCR → 다시 반영).

.\target\release\sdp.exe ocr .\tests\samples.txt --cache .\work\ocr_cache
화면(일부) — 아직 OCR 안 한 쪽만 읽는다
스캔_예시.pdf — 남은 쪽 [1,2]
    OCR 1/2 1228ms
    OCR 2/2 1423ms
  → {"pages":2,"skipped":0,"stopped":false}

그다음 캐시를 보면서 deferred 방식으로 파싱하면 OCR 을 다시 하지 않고 캐시 글을 쓴다:

.\target\release\sdp.exe parse .\tests\samples\스캔_예시.pdf --mode deferred --cache .\work\ocr_cache
--mode동작
inline (기본)파싱 중에 필요한 쪽을 바로 OCR 한다. 한 번 부르면 다 된다
deferred캐시에 있는 쪽만 쓰고, 없는 쪽은 결과의 ocr.pending 에 적어 돌려준다(나중에 ocr 명령으로 채움)

--cache 를 안 주면 캐시는 프로그램이 끝날 때 사라지는 메모리에만 둔다.
