## 3. 기법별 검토

### 3.1 패턴으로 제목 찾기 — 추천 높음

**문제**
- PDF 사례집 · Q&A 집은 "사례 15 …", "Q3. …" 같은 소제목이 헤딩이 아니라 보통 문단으로 읽힌다.
- `build_sections` 는 heading 블록에서만 절을 나누므로 여러 사례가 한 절에 섞인다.
  - 이러면 검색어가 사례 제목 단어에 걸리지 않는다.
  - 판단 모델이 "이 조각에 답이 있나" 를 사례 하나 단위로 보지 못한다.

**[측정]**
- `pdf.infer_headings = true` 로 열어도 청탁금지법 PDF 의 헤딩은 22개 그대로였다. 사례 제목은 잡히지 않았다.
- DecideRAG 규칙으로 문단을 heading 으로 바꾼 뒤 `p.chunk(doc)` 로 다시 자르면 사례 단위로 나뉜다.
  - 규칙: `^\s*(사례|Q\s*\d|질의)\s*\d*` 이고 60자 미만, 바꾼 level = 기존 최대 level + 1.

| | 기본 | 전처리 + `p.chunk` |
|---|---|---|
| 헤딩 블록 | 22 | 132 (사례 문단 110개 추가) |
| 청크 | 186 | 242 |
| 경로에 "사례" 가 있는 청크 | 8 | 226 |
| 경로 종류 | 22 | 116 |
| 다시 자르는 시간 | — | 0.02초 |

예: `[청탁금지법 Q&A 사례집 > 1. 인적 적용범위 > 사례 3 국회의원이'공직자등'에 해당하는지 여부]`

**[제안] 옵션**

```json
{"chunk": {
  "heading_patterns": ["^\\s*(사례|Q\\s*\\d|질의)\\s*\\d*", "^\\s*제\\s*\\d+\\s*조", "^\\s*별표\\s*\\d+"],
  "heading_max_chars": 60,
  "heading_level": "child"
}}
```

- `heading_patterns`: 이 패턴으로 시작하는 짧은 paragraph · list_item 을 제목으로 본다. 기본 빈 목록 (지금과 같음).
- `heading_max_chars`: 이보다 긴 문단은 본문으로 둔다. 본문 첫 줄이 우연히 "사례" 로 시작하는 경우를 막는다.
- `heading_level`: `"child"` = 지금 절의 한 단계 아래. 정수면 그 level.
- 넣을 곳: `crates\sdp-core\src\chunk\assemble.rs` 의 `build_sections`.
  - 지금 `if b.kind == B::HEADING` 인 곳에 "패턴에 맞는 짧은 문단" 조건을 더한다.
  - `regex` 크레이트는 이미 의존성에 있다 (`sdp-core\Cargo.toml`).
- 블록(`blocks`)은 바꾸지 않고 청킹에서만 제목으로 쓰면 `blocks_version` 을 올릴 필요가 없다. `chunk_version` 은 결과가 바뀌므로 올린다.

### 3.2 짧은 청크를 버리지 않고 합치기 — 추천 높음

**문제**
- 연동설명서는 "`min_tokens` 보다 짧은 청크는 버린다" 고 적고 있다.
- 규정 문서에는 "제5조 경조금은 50만원으로 한다." 처럼 짧지만 답이 되는 조항이 있다. 버리면 검색에서 사라진다.
- DecideRAG 청커는 본문이 150자 미만이면 제목에서 끊지 않고 다음 내용과 이어 붙인다. 버리지 않는다.

**[제안] 옵션**

```json
{"chunk": {"short": "merge"}}   // "drop" (지금) | "merge" (앞 또는 뒤 청크와 합침, 크기 상한 안에서)
```

- 기본 `min_tokens` 16 (chars 단위면 16자)이라 실제로 버려지는 양은 적을 것으로 보이나, 세어 보지 않았다 (미측정).

### 3.3 직전 짧은 줄 겹치기 — 추천 중간

- DecideRAG 청커는 크기 때문에 끊을 때, 직전 줄이 200자 미만이면 다음 청크 앞에도 넣는다.
  - 예: 표 앞의 "(단위 : 원)", 조항 머리 문장.
- DLL 의 `overlap` 은 한 줄이 크기를 넘어 토큰 창으로 자를 때만 쓰인다 (연동설명서).
- [제안] `carry_short_line_chars: 200` (0 = 끔).
- 효과는 재지 않았다.

### 3.4 한국어 문장 끝에서 자르기 — 확인 필요

- DecideRAG 청커는 긴 문단을 `(?<=[.다요음함\n])\s+` 에서 자른다.
- DLL 에는 `sentence_split` 옵션(기본 false)이 있다. 어떤 문장 경계를 쓰는지는 이번에 확인하지 않았다.
- 한국어 종결 어미("~다", "~함", "~음")를 경계로 쓰는지 확인하고, 아니면 더하기를 권한다.

### 3.5 문서 제목 다듬기 — 추천 낮음

- 파일 이름 "03.경조사지원규정_12.01.01.doc" → "경조사지원규정" (앞 `숫자.`/`숫자_`, 뒤 `_날짜`, `[1]` 제거).
- 지금도 `parse(path, title=…)` 로 넘기면 되므로 DLL 에 꼭 필요하지는 않다.
- 여러 언어에서 같은 제목을 원하면 `title_clean: true` 같은 옵션을 생각할 수 있다.

### 3.6 문장인데 제목으로 읽힌 블록 거르기 — 추천 중간

**[측정] 본 사례**
- 출장여비규정(doc)에서 "13.1.2 7.5. 규정에 따라 준비금을 지급할 수 있다." 가 heading 블록으로 읽혔다.
- 청크 경로 `13. 해외출장여비 > 13.1.2 7.5. 규정에 따라 준비금을 지급할 수 있다.` 에 문장이 통째로 들어갔다. DecideRAG 청커도 같다.

**[제안]**
- 청킹 때 heading 이 `heading_max_chars` 보다 길거나 "다." · "함." 으로 끝나면 본문으로 본다.

### 3.7 번호 체계로 제목 깊이 정하기 — 추천 중간

- [제안] 제목 앞 번호로 level 을 다시 매긴다. 파서가 준 level 이 어긋나도 경로가 바르게 쌓인다.
  - `1.` → 1, `1.2` → 2, `13.1.2` → 3, `가.` · `1)` → 한 단계 아래.
- 이번에 level 이 틀린 사례를 따로 세지는 않았다 (미측정).

### 3.8 글자층이 있어도 지정 쪽 OCR — 파싱 쪽, 추천 높음

**[측정] 문제**
- `37_청탁금지법_Q&A_사례집[1].pdf` 는 글자층에서 숫자가 빠져 있다. 213쪽 중 154쪽, 블록 707개.
  - 예: "제8조제1항" → "제 조제 항", "1인당 3만원" → "인당 만원".
- `pdf_ocr_pages` (`crates\sdp-core\src\ocr\mod.rs`)는 그림이 쪽을 덮고 글자층 글이 적은 쪽만 고른다. 이 쪽들은 대상이 아니다.
- 강제로 OCR 할 쪽을 주는 옵션도 없다.
- `ocr_pages` 로 캐시를 채워도 `parse` 는 `pdf_ocr_pages` 가 고른 쪽만 캐시를 본다 (`docmodel\pdf.rs`).

**지금 DecideRAG 가 하는 일**
- `ocr_file(path, 쪽 목록)` 으로 따로 OCR 하고, 글자층 블록에 숫자를 채운다 (3.9).

**[측정] OCR 시간** (이 PC, CPU 4스레드, `ocr_file`)

| 쪽 수 | 시간 |
|---|---|
| 5쪽 | 쪽당 1.85초 |
| 2쪽 | 쪽당 2.1초 |
| 154쪽 한 번에 | 600초 (쪽당 3.9초). 한 번에 많이 돌리면 느려진 원인은 확인하지 않았다 |

- OCR 결과 줄: `"청탁금지법에 따르면,누구에게든 1인당 3만원 이하의 식사만 살 수 있는"`, `"(제8조제1항,제2항,제4항,제5항 참조),"`.
  - 숫자는 돌아온다.
  - 띄어쓰기가 빠지는 곳이 있다: "근로를제공하는", ",직무".

**[제안] 옵션**

```json
{"ocr": {"force_pages": [9, 12, 13]}}            // 호출 옵션: 이 쪽은 글자층이 있어도 OCR
{"ocr": {"force_when": "missing_digits"}}        // 3.9 의 패턴이 보이는 쪽을 스스로 골라 OCR
```

### 3.9 PDF 글자층 숫자 빠짐 자동 보정 — 파싱 쪽, 추천 중간

**DecideRAG 구현** (`D:\Project\DecideRag\src\decide_rag\ocrfix.py`)
1. 흔적이 있는 쪽을 고른다: `제\s+조|조제\s+항|\s회\s+만원|\s+만원\s|제\s*조\s*제\s*항`.
2. 그 쪽만 `ocr_file` 로 OCR 한다.
3. 블록마다 글자층 글과 OCR 글을 한글 · 영문 글자만 남겨 맞춘다 (difflib).
4. 이웃한 두 글자가 OCR 에서도 바로 이웃하고 그 사이 틈에 숫자가 있을 때만 그 틈을 OCR 글로 바꾼다.
   - 나머지 띄어쓰기는 글자층 그대로 둔다.
   - 맞은 글자가 90% 미만이거나 OCR 쪽에서 흩어지면 바꾸지 않는다.
   - 표 블록은 건드리지 않는다.

**[측정] 결과**

| 방식 | 채운 블록 (707개 중) | 띄어쓰기 |
|---|---|---|
| OCR 글로 통째 바꾸기 (첫 시험) | 604 | 빠짐 |
| 숫자 틈만 바꾸기 (채택) | 668 (94.5%) | 글자층 유지 |

- 예: "제 조제 항 제 항 제 항 제 항 참조" → "제8조제1항 제2항 제4항 제5항 참조".
- 남은 39개는 숫자 말고 이름(甲 · 乙 등)도 빠진 블록이다 ("은 의 최초 부정청탁을…").

**[제안]**
- DLL 에 넣으면 다른 언어로 붙이는 시스템도 같은 결과를 얻는다.
- 결과 블록에 `source: "ocr_fix"` 같은 표시를 남기면 나중에 걸러 볼 수 있다.
- 블록 글이 바뀌므로 `blocks_version` 을 올리거나 옵션(기본 꺼짐)으로 둔다.

**[측정] DecideRAG 평가에서 본 것** (자세히는 DecideRAG 설계서 14.5)
- 정답률 차이: 전체 90문항 −0.001 [−0.028, +0.023], 이 문서 12문항 +0.010 [−0.044, +0.063]. 효과는 확인되지 않았다.
- 답에 숫자가 돌아왔다. 예: "1인당 7만원 상당의 식사 … 음식물 3만원 가액 한도".

## 4. 순서 제안

1. 3.1 패턴 제목, 3.2 짧은 청크 합치기 — DLL 청커를 DecideRAG 에서 쓸 수 있게 하는 최소 조건.

3. 3.8 지정 쪽 OCR — DecideRAG 의 `ocr_file` 별도 호출을 없앤다. 3.9 는 그 위에 얹는다.
4. 3.3 · 3.4 · 3.7 — 효과를 재 보고 정한다.
5. 그 뒤 DecideRAG 에서 DLL 청커와 지금 청커를 근거 포함률 · 정답률로 비교한다 (미실행).

## 5. 확인하지 않은 것

- 3.1 · 3.2 · 3.3 · 3.6 · 3.7 을 넣었을 때의 검색 · 정답률 효과. 3.1 은 청크 모양(사례 단위 경로)만 확인했다.
- DLL `sentence_split` 의 문장 경계 규칙.
- `min_tokens` 로 실제 버려지는 청크 수.
- OCR 을 한 번에 많이 돌릴 때 쪽당 시간이 늘어나는 원인.

## 6. 구현 기록 — struct_docparse 0.4.0 (2026-11-27)

9개 기법을 모두 **옵션(기본 꺼짐)**으로 넣었다. 끄면 0.3.1과 글자 하나까지 같다(SimpleRAG 샘플 41건 + 이 문서의 시험 문서 18건 × 설정 4가지, 청크 · chunking · blocks 236/236, 청크 14,389개). 그래서 `chunk_version` 1 · `blocks_version` 7을 올리지 않았다(3.1의 "chunk_version 을 올린다"는 기본 결과가 바뀔 때의 이야기 — 켠 옵션은 결과 `chunking`에 적힌다).

| # | 옵션 | 넣은 곳 |
|---|---|---|
| 3.1 | `chunk.heading_patterns` · `heading_max_chars`(60) · `heading_level`("child" · 1~9) | `chunk/headings.rs` `promote_patterns` — `build_sections` 앞에서 문서 사본의 문단을 제목으로 |
| 3.2 | `chunk.short`: "drop" · "merge" | `chunk/pack.rs` `finish_short` — 앞 청크 뒤, 안 되면 다음 청크 앞(hard_max 이하), 못 붙이면 남김 |
| 3.3 | `chunk.carry_short_line_chars` | `pack_units` — 크기로 끊을 때 마지막 짧은 줄을 다음 조각 앞에(표 행 · 머리글 제외, 그 줄만 든 조각은 안 만듦) |
| 3.4 | `chunk.sentence_endings`: "basic" · "ko" | 확인 결과 기존 `sentence_split`은 `(?<=[.!?。])\s+` — 마침표 없는 종결 어미를 못 봐서 "ko" = `(?<=[.!?。다요음함])\s+` 를 더했다 |
