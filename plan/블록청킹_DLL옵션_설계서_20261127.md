# 블록 단위 청킹을 DLL 옵션으로 — 설계서

> 2026-11-27 · 대상: struct_docparse 0.2.0 → 0.3.0 (ABI 1 유지) · 원본 코드: `D:\Project\SimpleRAG\rust\simplerag\src\chunk.rs` · `docmodel\assemble.rs`

## 1. 한 줄 요약

SimpleRAG(Rust 판)가 DLL 결과 블록을 받아 **자기 쪽에서** 하던 "블록 → 절 → 토큰 예산 청크" 작업을 DLL 안으로 옮긴다.
`sdp_parse` 호출 옵션에 `"chunk": {...}` 를 주면 결과 JSON 에 `"chunks": [...]` 가 함께 나온다. 주지 않으면 지금과 글자 하나까지 같다.
청크 크기는 SimpleRAG 와 같은 **e5 tokenizer.json 토큰 수**로 잰다(경로를 옵션으로 받음). 토크나이저가 없으면 글자 수로 잰다.

얻는 것:

- SimpleRAG 밖의 호스트(Python · Java · PHP · C)도 같은 청크를 바로 받는다 — 지금은 블록만 받고 청킹은 각자 다시 짜야 한다.
- 추출과 청킹이 한 저장소에서 같이 버전을 올린다. 블록 모양이 바뀌면 청킹도 같은 커밋에서 맞춘다.
- SimpleRAG 는 `chunk.rs` · `assemble.rs`(약 770줄)를 나중에 지울 수 있다.

## 2. 지금 모양 (SimpleRAG Rust 판)

### 2.1 흐름

```
indexer::parse_doc / extract_chunks / extract_metas
  └ extract_blocks_keep(path, name, tok)
      ├ docmodel::extract_document_keep → docparse::parse → sdp_parse  (DLL — 블록 JSON)
      │   └ docparse::doc_from_json  (JSON → Document)
      └ chunk_mode == "structured" ?
          ├ 예 → chunk::split_blocks(&mut doc, tok, None)       → Vec<ChunkMeta>
          │       ├ doc.is_blocks() 아니면(폴백 평문) split_structured(raw_text)
          │       ├ assemble::build_sections  (제목 수준 스택으로 절 나누기)
          │       ├ assemble::section_units   (제목 · 블록 · 표 행 = 단위)
          │       ├ 작은 절은 이어 묶고, 큰 절은 pack_units 로 자르기
          │       ├ PageFinder 로 청크마다 실제 쪽 찾기
          │       └ enforce_hard_max (e5 입력 한계 510)
          └ 아니오 → split_text(full_text) (토큰 창 + 겹침)
```

DLL 은 지금 **블록까지만** 낸다. 절 조립과 청킹은 "검색용 가공"이라 SimpleRAG 에 남겼다(`docmodel/mod.rs` 머리 주석).
Python 판(`src/simplerag/chunk.py`)은 DLL 을 쓰지 않고 자기 docmodel 로 같은 규칙을 돈다 — 이번 작업 대상이 아니다.

### 2.3 청킹 설정 (SimpleRAG `config.yaml chunk.*`)

| 키 | 기본 | 뜻 |
|---|---|---|
| `chunk.tokens` | 128 | 청크 목표 크기(토큰) |
| `chunk.overlap` | max(8, tokens/8) | 큰 단위를 토큰 창으로 자를 때 겹침 |
| `chunk.min_tokens` | 16 | 이보다 짧은 청크는 버림 |
| `chunk.table_header_max_tokens` | 64 | 이보다 긴 표 머리글은 다시 붙이지 않음 |
| `chunk.mode` | structured | structured = 절 단위 / 그 밖 = 고정 크기 |
| `chunk.table_whole` | 384 | 표 글이 이 이하면 행으로 나누지 않음(0 = 끔) |
| `chunk.overflow_ratio` | 1.0 | 약한 초과 α — 예산 × α 안이면 단위를 통째로 |
| `chunk.sentence_split` | false | 넘치는 줄을 문장 경계로도 나눔 |
| `chunk.hard_max` | 510 | 절대 상한(e5 입력 한계) |

이 9개가 그대로 DLL 청킹 옵션이 된다(이름은 `chunk.` 아래에 같게).

## 4. 핵심 결정 — 토큰을 어떻게 세나

SimpleRAG 청크는 e5 토큰 수로 잘리고, 고정 크기 모드 · 상한 넘김은 **토큰 id 를 다시 글로 되돌린(decode) 글**이 청크가 된다.
그래서 같은 청크를 내려면 DLL 도 같은 토크나이저를 써야 한다.

| 안 | 방법 | 좋은 점 | 나쁜 점 |
|---|---|---|---|
| **A (권장)** | 열 때 옵션 `chunk.tokenizer` = tokenizer.json 경로. DLL 이 `tokenizers` 크레이트로 적재 | 어느 언어 호스트든 경로 하나로 SimpleRAG 와 같은 청크. decode 도 같음 | DLL 이 `tokenizers`(+ onig C 코드)를 품어 커진다. SimpleRAG 와 두 벌 적재(메모리) |
| B | 토큰 수 세기 콜백 `sdp_set_token_counter(h, fn, user)` | 호스트 토크나이저 한 벌만 | decode 가 안 돼 고정 크기 · 상한 넘김 결과가 달라짐. 단위마다 FFI 왕복(느림). 함수 추가 |
| C | 글자 수만 | 가볍다 | SimpleRAG 와 청크가 다르다 → 재색인 필요 |

**결정: A 를 기본으로, 토크나이저 경로가 없으면 C(글자 수)로 동작.**

- `chunk.unit`: `"tokens"`(기본, 토크나이저 필요) / `"chars"`(글자 수 — 이때는 `tokens` · `overlap` · `hard_max` 등 모든 크기 값이 **글자 수** 뜻이다. 환산 비율을 두면 창 자르기(id = 글자)와 예산 비교의 단위가 어긋나서 1단계 구현에서 뺐다).
- `unit = tokens` 인데 토크나이저를 못 읽으면 `sdp_open` 이 아니라 **첫 청킹 호출**에서 `SDP_EINVAL "chunk.tokenizer 를 읽지 못함: …"` (청킹을 안 쓰는 호스트가 열기에 실패하지 않게).
- `tokenizers` 기능은 SimpleRAG 와 같게 `default-features = false, features = ["onig"]` · 같은 0.21 — 같은 토큰을 보장. 리눅스 빌드서버(CentOS 7 · gcc 4.8.5)에서도 빌드되고 토큰이 같음을 확인했다(부록 B).
- 메모리: 두 벌 적재 비용을 실측해 연동설명서에 적는다(§9). 크면 B 안을 나중 단계로 검토.

## 5. 바깥 모양 (API)

ABI 버전은 **1 그대로**. 함수 인자를 바꾸지 않고, 옵션 키와 함수 하나를 **더하기만** 한다(`api.rs` 규칙: 빼거나 인자를 바꿀 때만 올림).

### 5.1 열 때 옵션 — 최상위 `chunk` 추가 (기본값 묶음)

```json
{
  "ocr": {...}, "pdf": {...}, "runtime": {...},
  "chunk": {
    "tokenizer": "D:/SimpleRAG/models/e5-small-ko/tokenizer.json",
    "unit": "tokens",
    "mode": "structured",
    "tokens": 128, "overlap": 16, "min_tokens": 16,
    "table_header_max_tokens": 64, "table_whole": 384,
    "overflow_ratio": 1.0, "sentence_split": false, "hard_max": 510,
    "prefix": true, "prefix_max_chars": 80
  }
}
```

- 여기 준 값은 **기본값**일 뿐, 청킹은 켜지지 않는다. 켜는 것은 호출마다(§5.2).
- 모르는 키는 지금처럼 `EINVAL`(오타를 조용히 넘기지 않음).
- 값 검사는 SimpleRAG `config.rs check_resolved` 와 같은 범위: `tokens ≥ 1`, `overlap < tokens`, `min_tokens ≤ tokens`, `hard_max ≤ 510`(unit=tokens 일 때), `overflow_ratio ≥ 1.0` 등.
- `sdp_set_option("chunk.tokens", "256")` 처럼 실행 중에 바꿀 수 있다. `chunk.tokenizer` 를 바꾸면 다음 청킹 때 새로 적재.
- `prefix` = 청크 앞에 `[문서 > 절]\n` 을 붙이나(SimpleRAG 는 붙임). `prefix_max_chars` = 접두 길이 상한(지금 80 고정).

### 5.2 호출 옵션 — `sdp_parse` call_opts 에 `chunk` 추가

```json
{"title": "인사규정", "chunk": {"enabled": true, "tokens": 256}}
```

- `chunk.enabled: true` 일 때만 청킹. 나머지 키는 열 때 기본값을 이 호출에서만 덮어쓴다.
- `"chunk": true` 는 `{"enabled": true}` 의 줄임.
- 옛 DLL(0.2.x)은 모르는 호출 옵션이라 `EINVAL "모르는 호출 옵션: chunk"` — 호스트는 이것 또는 버전 문자열로 지원 여부를 안다(§7).
- `keep_pages` 와 함께 써도 된다(비슷한 문서 찾기가 고른 쪽만 청킹 — SimpleRAG `extract_metas` 가 이 경우).

### 5.3 결과 JSON — `chunks` · `chunking` 추가

```json
{
  "schema": 1, "blocks_version": 7, "chunk_version": 1, "format": "docx", "title": "인사규정",
  "blocks": [ ... 지금과 같음 ... ],
  "chunking": {"unit": "tokens", "mode": "structured", "tokens": 128, "overlap": 16, "min_tokens": 16,
               "table_whole": 384, "overflow_ratio": 1.0, "sentence_split": false, "hard_max": 510,
               "tokenizer": "tokenizer.json"},
  "chunks": [
    {"no": 0, "text": "[인사규정 > 제1장 총칙]\n제1조(목적) …", "tokens": 121,
     "section_id": 0, "path": ["제1장 총칙"], "source": "parser",
     "page": 1, "page_from": 1, "page_to": 2}
  ]
}
```

- 청크 필드는 SimpleRAG `ChunkMeta` + `dump_chunks` 와 같은 이름 · 같은 뜻. `tokens` 는 `unit` 기준 길이.
- `section_id` · `path` · `page*` 가 없으면 `null` / `[]`(폴백 평문 · 고정 크기 모드).
- `source`: 블록 경로는 첫 절 제목의 출처(parser · inferred · regex · ocr), 폴백 평문은 `"legacy"`, 고정 크기는 `""`(SimpleRAG 와 같게).
- `chunking` 은 실제로 쓴 설정(덮어쓰기 반영) — 크기를 바꿔 비교할 때 어느 값으로 잘렸는지 남긴다.
- **`blocks` 는 바뀌지 않는다.** `build_sections` 가 블록 `path` 를 채우는데, 청킹은 Document 사본에서 돌려 블록 JSON 은 청킹을 켜도 끄도 같게 한다.
- 청킹 결과가 0개여도 오류가 아니다(`"chunks": []`). "추출 텍스트 없음" 판정은 호스트 몫(SimpleRAG `parse_doc` 그대로).
- deferred OCR 로 남은 쪽이 있으면 그 쪽 글이 빠진 청크다 — OCR 뒤 다시 `sdp_parse` 하면 새 청크가 나온다(지금 SimpleRAG 흐름과 같음).

### 5.4 새 함수 — `sdp_chunk` (다시 자르기)

```c
/* sdp_parse 결과 JSON(블록) → 청크만 다시. 파싱 · OCR 없이 크기만 바꿔 보는 용도 */
int32_t sdp_chunk(SdpHandle* h, const char* doc_json, const char* chunk_opts_json, char** out_json);
/* out: {"chunk_version":1, "chunking":{...}, "chunks":[...]} */
```

- `doc_json` 은 `sdp_parse` 결과 그대로(`blocks` · `raw_text` · `title` 필요). 블록 JSON 을 저장해 둔 호스트가 재파싱 없이 다시 자를 수 있다(SimpleRAG `extract --blocks --dump` 진단, 크기 실험).
- `chunk_opts_json` 은 §5.2 의 `chunk` 객체와 같은 모양(`enabled` 는 없어도 켜진 것으로 본다). null 이면 열 때 기본값.
- 오류: JSON 모양이 틀리면 `EINVAL`, 토크나이저 못 읽음 `EINVAL`, 내부 패닉 `EPANIC`.
- 함수를 **더하는** 것이라 ABI 1 유지. 옛 DLL 에는 이 심볼이 없다 → 호스트는 심볼이 없으면 이 기능만 끈다.

### 5.5 버전 문자열

`sdp_version()` = `"0.3.0 blocks=7 chunk=1 ocr=…"` — `chunk=` 가 있으면 청킹을 지원한다.

## 6. 안쪽 구조 (sdp-core)

```
crates/sdp-core/src/
  chunk/
    mod.rs        — ChunkOpts(옵션 한 벌) · ChunkMeta · chunk_document(doc, opts) 입구 · CHUNK_VERSION
    tok.rs        — Measure 트레잇(len · ids · decode) + HfTok(tokenizers) · CharMeasure(글자 수)
    assemble.rs   — Section · build_sections · section_units · make_prefix · label_of (SimpleRAG 에서 그대로)
    pack.rs       — split_blocks · pack_units · peel_heading_only · split_unit · split_oversized · enforce_hard_max
    fixed.rs      — chunk_ids · split_text · split_structured (structure.rs 재사용)
    pagefind.rs   — PageFinder · unit_pages
  api.rs          — call_opts.chunk 읽기 · parse 결과에 chunks 붙이기 · chunk(doc_json, opts)
  config.rs       — Options.chunk(열 때 기본값) · 값 검사
  docmodel/blocks.rs — Document::from_json (SimpleRAG docparse::doc_from_json 을 옮김, sdp_chunk 용)
crates/sdp-ffi/src/lib.rs — sdp_chunk 내보내기
```

옮기는 규칙:

1. **로직은 한 줄도 바꾸지 않고 옮긴다.** 바뀌는 것은 `cfg()` 전역을 읽던 자리를 `&ChunkOpts` 인자로 받는 것, `&Tok` 를 `&dyn Measure` 로 받는 것뿐.
   - 이유: 청킹 옵션은 호출마다 덮어쓰므로 전역(프로세스에 한 벌)에 두면 스레드끼리 섞인다. OCR 덮어쓰기처럼 스레드별 값을 쓰지 않고 그냥 인자로 넘긴다.
2. `Measure::len` 은 SimpleRAG `Tok::tlen` 처럼 캐시를 둔다(2만 개 넘으면 비움). 캐시는 토크나이저 객체에 붙어 핸들끼리 함께 쓴다(Mutex).
3. 토크나이저는 `OnceLock<RwLock<Option<(경로, Arc<HfTok>)>>>` — 첫 청킹 때 적재, 경로가 바뀌면 다시.
4. `CharMeasure` 의 `ids` · `decode` 는 글자(char) 배열 자르기로 같은 자리를 대신한다(토큰 창 = 글자 창).
5. `CHUNK_VERSION` = 1. **청크 결과가 바뀌는 코드 변경마다 올린다**(BLOCKS_VERSION 과 같은 규칙). 블록이 바뀌면 청크도 바뀌지만 그건 blocks_version 이 이미 알린다.

## 7. 호환 · 버전

| 상황 | 동작 |
|---|---|
| 새 DLL + 청킹 안 쓰는 호스트 | 지금과 글자 하나까지 같다 — `chunk_version` · `chunking` · `chunks` 는 청킹을 켠 호출에만 넣는다 |
| 새 DLL + 청킹 쓰는 호스트 | `chunks` 를 받는다 |
| 옛 DLL + 청킹 쓰는 호스트 | `sdp_version` 에 `chunk=` 가 없음 → 호스트 자기 청킹으로. 실수로 보내도 `EINVAL` 이라 조용히 틀리지 않는다 |
| 재색인 판정 | 호스트는 `blocks_version` 과 `chunk_version` 을 **둘 다** 색인 상태에 적고, 하나라도 바뀌면 다시 자른다 |

`schema` 는 1 유지 — 키를 더하기만 하고 뜻을 바꾸지 않는다.

## 8. SimpleRAG 전환 단계

| 단계 | SimpleRAG 쪽 변경 | 끝 조건 |
|---|---|---|
| S1 | `docparse.rs open_options()` 에 `chunk` 묶음(config.yaml `chunk.*` 9개 + `tokenizer` = 임베딩 모델 폴더의 tokenizer.json) | 새 DLL 로 열기 성공 |
| S2 | `docparse::parse_chunks(path, title, keep) -> (Document, Vec<ChunkMeta>)` 추가 — `chunk=` 지원이면 `call_opts.chunk.enabled=true`, 아니면 `None` | – |
| S3 | `indexer::extract_blocks_keep` 이 S2 결과가 있으면 그것을 쓰고, 없으면 지금의 `split_blocks` / `split_text` | 같음 비교(§9.1) 통과 |
| S4 | 색인 상태에 `chunk_version` 저장 · 비교(지금 `blocks_version` 옆) — 0.1.6 의 "블록 버전만 오르면 재구축 없이 이어서 색인" 규칙에 청크 버전도 넣는다 | 버전 올린 DLL 로 이어 색인 시험 |
| S5 | `cli.rs extract --blocks --dump` 의 chunks.json 을 DLL 결과로 | – |
| S6 | (한두 릴리스 뒤) `chunk.rs` 의 블록 청킹 · `assemble.rs` 삭제. `Tok` 는 BM25 용으로 남김 | 옛 DLL 지원 끝낼 때 |

`extract.engine = legacy` 경로(`sdp_extract_text` + `split_structured`)는 S6 까지 그대로 둔다 — 블록 경로의 폴백 평문은 DLL 이 이미 `split_structured` 로 자른다.

## 9. 검증

### 9.1 같음 비교 (가장 중요)

- `sdp-cli` 에 `chunk` 명령을 더한다: `sdp chunk <파일|목록> --tokenizer <tokenizer.json> [--tokens 128 …] --out <폴더>` → `<파일>.chunks.json`(SimpleRAG `dump_chunks` 와 같은 모양).
- SimpleRAG 의 `extract --blocks --dump` 가 쓴 chunks.json 과 **글자 하나까지** 같은지 `sdp compare` 로 본다(이미 있는 `first_diff` 재사용).
- 대상: SimpleRAG `sample/` · `sample_pdf/` 전부 + 기존 회귀 묶음(docx · pptx · xlsx · hwpx · doc · hwp · pdf 표 · 스캔 OCR · md · html).
- 설정 조합: 기본 · `tokens 256/512` · `table_whole 0` · `overflow_ratio 1.2` · `sentence_split true` · `mode fixed`.
- 통과 기준: 모든 파일 · 모든 조합에서 `chunks` 배열 완전 일치(text · tokens · section_id · path · source · page · page_from · page_to).

### 9.2 단위 시험 (`tests/`)

- 제목만 든 절이 다음 절 첫 청크로 넘어가는가(peel).
- 표가 예산을 넘을 때 조각마다 머리글 행이 붙는가 · 머리글이 조각 끝에 홀로 남지 않는가.
- 통째 표(`table_whole`)가 hard_max 안에서 쪼개지지 않는가.
- hard_max 를 넘는 단위가 510 이하로 잘리는가.
- 같은 글귀가 되풀이되는 절에서 PageFinder 가 순서대로 쪽을 찾는가.
- `unit=chars` 에서 토크나이저 없이 동작하는가.
- 청킹을 켜도 `blocks` JSON 이 같은가.
- 잘못된 옵션(`overlap ≥ tokens`, 모르는 키) → `EINVAL`.

### 9.3 성능 · 메모리

- 청킹 시간: SimpleRAG 에서 잰 값과 같은 수준인지(옮기기만 하므로 같아야 한다) — `bench/rust_vs_py/perf.py` 묶음.
- FFI 결과 JSON 이 커지는 비용: 청크 글이 블록 글과 거의 겹쳐 결과가 대략 2배. 큰 PDF(300쪽 이상) 한 개로 직렬화 · 해제 시간을 잰다.
- 토크나이저 두 벌 적재 메모리(SimpleRAG + DLL)를 작업 관리자 기준으로 재어 연동설명서에 적는다.

## 부록 B. tokenizers 시험 빌드 결과 (2026-11-27)

시험 방법: 저장소를 건드리지 않고 사본에 `tokenizers = "=0.21.4"`(`default-features = false, features = ["onig"]` — SimpleRAG 와 같은 버전 · 기능, Cargo.lock 의 onig_sys 69.9.3 도 같음)를 sdp-ffi 에 넣었다. 시험 함수 `sdp_tok_probe` 는 e5-small-ko tokenizer.json 으로 글 803줄을 줄마다 토큰화 · 되돌리기(decode)하고 해시를 낸다. 빌드서버의 따로 된 폴더(`<빌드폴더>_tokprobe`, `_tokprobe_base`)에서 빌드했다.

| 항목 | Windows (MSVC) | 리눅스 (CentOS 7 · glibc 2.17 · gcc 4.8.5 · rustc 1.95) |
|---|---|---|
| onig(C) 컴파일 | 성공 | **성공** |
| 토큰 결과 (803줄, 18,024토큰) | ids `a4b0702d602fb820` · decode `a96dc3ccedf38f42` | **같음** |
| tokenizer.json(17 MB) 적재 | 695 ms | 650 ms |
| 803줄 토큰화 + decode | 47 ms | 29 ms |
| DLL 크기 | 5.23 MB → 7.32 MB (+2.1 MB) | 5.50 MB → 7.66 MB (+2.1 MB) |
| 최고 요구 glibc | – | **2.15 → 2.17** |
| 의존 라이브러리 | – | 새로 붙는 것 없음(librt 는 오히려 빠짐) |

glibc 가 오른 이유: 새로 요구하는 기호는 `clock_gettime`(2.17 판) · `clock_nanosleep`(2.17) · `getauxval`(2.16) 셋이다.
같은 서버 · 같은 툴체인으로 지금 HEAD 를 빌드한 대조판은 2.15 그대로라 원인은 tokenizers 를 넣은 것이다.
다만 의존 크레이트(.rlib · onig .a)에는 이 기호를 부르는 곳이 없어, tokenizers 가 끌어오는 rayon 스레드 등이 쓰는 **Rust 표준 라이브러리 쪽**으로 추정한다. librt 가 링크에서 빠지면서 `clock_gettime` 도 libc 의 2.17 판으로 묶였다.
CentOS 7 이 2.17 이라 실제 배포 대상에는 영향이 없다고 본다.

메모리(토크나이저 두 벌)는 아직 재지 않았다. 1단계 구현 뒤 §9.3 에서 잰다.

## 부록 A. 청킹 규칙 요약 (옮길 동작 그대로)

1. **절 나누기** — 머리글 · 바닥글 · 쪽 번호 · 목차 블록은 뺀다. 제목 블록 수준으로 경로 스택을 쌓고, 제목이 나올 때마다 새 절. 첫 제목 앞은 경로 없는 머리말 절.
2. **단위** — 절 제목 한 줄 · 블록 하나 · 표는 머리글 묶음 + 행 하나씩(행에는 머리글을 기억해 둔다). `table_whole` 이하 표는 표 전체가 한 단위.
3. **작은 절** — 접두 + 단위 전부가 예산 이하면 앞 절들과 이어 묶는다(`\n\n` 으로). 넘치면 앞 묶음을 내보내되, 묶음 끝의 '들어오는 절의 상위 제목뿐인 절'은 떼어 새 묶음으로 넘긴다.
4. **큰 절** — 예산 = `tokens − 접두 길이`(최소 min_tokens). `pack_units` 로 단위를 채우고, 넘치면 끊는다. 표 머리글 단위가 첫 행과 같이 못 들어가면 먼저 끊는다. 새 조각이 값 행으로 시작하면 머리글을 다시 붙인다(`table_header_max_tokens` 이하일 때). 제목 줄만 든 조각은 끊지 않고 다음 단위와 함께.
5. **넘치는 단위** — 예산 × α 이하이거나 통째 표이면(그리고 hard_max 이하) 통째로. 아니면 줄 → (sentence_split 이면 문장) → 토큰 창(overlap)으로.
6. **쪽** — 청크 머리 24자(공백 뺀)를 첫 절 글에서 앞 청크 자리 뒤부터 찾고(못 찾으면 40 · 80 · 120자 뒤에서 다시), 꼬리 24자를 마지막 절 글에서 찾아 시작 쪽 · 쪽 범위. 못 찾으면 절 쪽 범위.
7. **마무리** — hard_max 넘는 청크는 토큰 창으로 다시 자르고, min_tokens 미만 청크는 버린다.
8. **폴백 평문**(블록 없음) — `structure::split_sections`(조문 · 번호절 문법 감지)로 절을 나눠 같은 방식으로 묶고, 표 줄(`|`) 조각에 머리글 줄을 다시 붙인다. `source = "legacy"`.
9. **고정 크기 모드** — 문서 전체 글(합성 아닌 블록을 줄로 이음)을 토큰 창 + 겹침.
