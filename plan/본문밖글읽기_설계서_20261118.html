본문 밖 글 읽기 설계서 — PDF 글상자 주석 · 서식 칸 · docx 메모 · SmartArt (사이냅과 맞추기)

D:\sample\scanpdf\2.pdf 에서 DocParse-rust 가 PDF 글상자 주석의 글을 읽지 못하는 버그가 보고됐다. 이 저장소도 같은지 살펴보니, 글자층을 읽는 곳은 똑같이 주석을 읽지 않는다. 다만 스캔 쪽은 OCR 이 주석을 그림으로 그려 읽어서 버그가 가려져 있었다. DocParse-rust 쪽에서 사이냅(snf_exe)과 견준 결과 PDF 말고도 docx 메모와 SmartArt 에서 같은 빈틈이 나왔고, 이 저장소에서 다시 재 봐도 같았다. 이 문서는 이런 본문 밖 글을 기본으로 읽도록 고치는 방법을 정한다. 코드는 아직 바꾸지 않았다.

1. 요약

버그는 이 저장소에도 있다글자층을 읽는 pdfium::read_pages_keep 는 FPDFText_* 로 쪽 본문만 읽는다. 주석 API(FPDFAnnot_*)는 하나도 불러오지 않는다. OCR 을 끄면 2.pdf 의 주석 글 8개가 모두 빠진다.
OCR 이 가려 주고 있었다쪽을 그릴 때 FPDF_ANNOT 를 주므로 보이는 주석이 그림에 들어간다. 그래서 기본 설정(OCR 켬)에서는 2.pdf 의 주석 글이 OCR 로 읽힌다. 하지만 글자층이 있는 보통 쪽은 OCR 하지 않으므로, OCR 을 켜도 그 쪽의 주석 글은 빠진다.
PDF 만의 문제가 아니다사이냅은 읽고 이 저장소는 안 읽는 것: PDF 글상자 · 숨긴 글상자 · 서식 칸 값, docx 메모, pptx SmartArt(실제 문서에서 12줄 차이). DocParse-rust 쪽 측정과 같다.
제안옵션 "extra_text"(기본 켬)로 위 다섯 가지를 읽는다. 숨긴 PDF 글상자도 사이냅처럼 읽는다. 본문이 늘어나므로 결과 바뀜 → 0.2.0. 옵션 이름 · 기본값은 DocParse-rust 와 맞춘다.

4. 지금 구조

4-1. PDF 를 읽는 곳

곳하는 일주석
pdfium.rs read_pages_keep쪽마다 글자층 글 · 글꼴 크기 · 표 · 그림 객체(OCR 켬일 때)를 PageText 로 모은다안 읽음
docmodel/pdf.rs extract_keep구조 추출. 글자층 줄을 블록으로 만들고, 스캔 쪽은 OCR 캐시 줄을 쪽 끝에 붙인다. 글자가 20자 미만이고 OCR 대기 쪽도 없으면 "텍스트층 없음" 오류를 내고 legacy 로 폴백한다—
legacy.rs pdf_text폴백 · 평문 추출. 쪽 글을 \n 으로 잇는다—
api.rs pdf_page_textsSimpleRAG 쪽 찾기 용. 쪽별 글자층 글—
ocr/run.rs pdf_scan_pagesOCR 할 쪽 고르기(추출과 같은 판정)—
pdfium.rs render_page_cappedOCR 용으로 쪽 그리기. FPDF_RenderPageBitmap(…, 0x01 = FPDF_ANNOT)보이는 주석은 그림에 들어간다. 숨긴 주석은 그리지 않는다

4-2. 바꾸면 안 되는 두 판정

  • 스캔 쪽 판정(ocr::pdf_ocr_pages)은 PageText.text 의 글자 수를 센다(10자 미만 + 그림이 30% 이상 덮음 등). 주석 글을 text 에 섞으면 스캔 쪽이 글 쪽으로 잘못 판정되어 OCR 이 빠진다. 그래서 주석 글은 따로 담는다.
  • 겹친 OCR 줄 빼기(ocr::drop_overlapping)는 글자층 글자 상자와 절반 이상 겹친 OCR 줄을 버린다. 주석 글은 글자층에 없으므로, 그림 속 주석을 OCR 로 읽은 줄은 지금도 남는다. 이 동작은 바꾸지 않는다(6-3).

4-3. Office 형식

  • docmodel/docx.rs: 본문 · 표 · 머리글/꼬리글 · 각주는 읽는다. word/comments.xml · word/diagrams/ 는 열지 않는다.
  • docmodel/pptx.rs: 슬라이드 순서대로 도형 글을 읽고, 관계(ooxml::rels)에서 notesSlide 를 따라가 노트를 읽는다. diagramData 관계는 무시한다.
  • docmodel/xlsx.rs · legacy.rs: 메모를 파일 이름 정규식으로 찾는다(3-2).

6. PDF 설계

6-1. 주석 읽기 — pdfium 함수 추가

이 저장소의 pdfium.dll(chromium/7999)이 아래 함수를 모두 내보내는 것을 확인했다. 새 C 라이브러리는 필요 없고, Api 구조체에 sym! 로 더하면 된다.

함수쓰임
FPDFPage_GetAnnotCount · FPDFPage_GetAnnot · FPDFPage_CloseAnnot쪽의 주석을 차례로 열고 닫는다
FPDFAnnot_GetSubtype종류: 1 = Text, 3 = FreeText, 13 = Stamp, 20 = Widget
FPDFAnnot_GetFlags숨김(0x02 Hidden · 0x20 NoView) 여부. 건너뛰는 데 쓰지 않는다. OCR 쪽에서 붙일지를 가리는 데만 쓴다(6-3)
FPDFAnnot_GetStringValue(annot, "Contents", …)FreeText 글(UTF-16LE). 길이를 먼저 묻고 버퍼를 잡는 두 번 호출 방식
FPDFAnnot_GetRect주석 자리(쪽 좌표). 쪽 안 순서(위 → 아래, 왼 → 오른)로 줄을 세울 때 쓴다
FPDFDOC_InitFormFillEnvironment · FPDFDOC_ExitFormFillEnvironment · FPDFAnnot_GetFormFieldType · FPDFAnnot_GetFormFieldValue서식 칸 값. 값은 위젯이 아니라 부모 필드 사전(/V)에 있는 경우가 많아 GetStringValue 로는 못 읽는다. 문서마다 서식 환경을 한 번 열고(빈 FPDF_FORMFILLINFO, version 2) 다 읽은 뒤 닫는다

서식 칸은 글 칸(text field)과 콤보/목록 칸의 값만 읽는다. 체크 상자 · 라디오 단추 값(Yes/Off)은 뜻 있는 글이 아니라서 읽지 않는다. 같은 필드가 여러 위젯으로 나뉘어 있어도 값은 한 번만 넣는다(필드 이름으로 거른다). 빈 값은 넣지 않는다.

6-2. 담는 자리 — PageText.extra

pub struct PageText {
    pub text: String,          // 지금처럼 글자층 글만 — 스캔 판정 · 표 · 글꼴 크기가 이것을 본다
    …
    pub extra: Vec<ExtraText>, // 새 칸 — 이 쪽의 본문 밖 글 (extra_text 켬일 때만 채운다)
}

pub struct ExtraText {
    pub kind: ExtraKind,       // FreeText | FormField
    pub text: String,          // /Contents 또는 서식 칸 값 (앞뒤 공백 정리, 안쪽 줄바꿈은 둔다)
    pub hidden: bool,          // /F Hidden · NoView — OCR 그림에 안 그려진다
    pub rect: [f32; 4],        // 쪽 좌표 — 줄 순서용
}
  • read_pages_keep 이 쪽을 연 김에 주석도 읽는다. 쪽을 두 번 열지 않는다. 쪽 상한 · 시간 상한도 같은 루프를 따른다.
  • 한 쪽 안의 주석은 rect 기준으로 위 → 아래, 같은 높이면 왼 → 오른 순서로 둔다. 주석이 저장된 순서는 편집한 순서라서, 쪽 위에서 보이는 순서와 다르다.
  • 스캔 판정(pdf_ocr_pages)은 text 만 본다. 그래서 옵션을 켜든 끄든 OCR 할 쪽이 같다.

6-3. OCR 쪽과 겹치지 않게

스캔 쪽은 OCR 이 그림 속 보이는 주석을 이미 읽는다(2장). 거기에 /Contents 를 또 붙이면 같은 글이 두 번 들어간다. 두 가지 안을 견줬다.

안방법좋은 점나쁜 점
A (제안)OCR 할 쪽(완료 · 대기 모두)에서는 보이는 주석을 붙이지 않는다. OCR 이 그림에서 읽는다. 숨긴 주석은 그림에 없으므로 /Contents 로 붙인다. OCR 하지 않는 쪽(글자층 쪽, OCR 끔)은 숨김 여부와 상관없이 모두 붙인다OCR 캐시 · 렌더링 · 겹침 규칙을 건드리지 않는다. 0.1.x 캐시를 그대로 쓴다스캔 쪽의 보이는 주석 글은 OCR 품질이다(2.pdf 에서는 정확했다)
BOCR 줄 중 주석 상자와 겹친 줄을 빼고, 모든 쪽에 /Contents 를 붙인다(drop_overlapping 에 주석 상자를 더함)주석 글이 늘 정확하다겹친 줄 빼기는 OCR 할 때 캐시에 굳는다. 0.1.x 캐시에는 이미 주석 OCR 줄이 들어 있어 두 번 들어간다. 그래서 캐시 판을 올리고 다시 OCR 해야 한다. 회전된 쪽의 좌표 변환도 맞춰야 한다

A 를 고른다. 쪽마다 정리하면 아래와 같다.

쪽보이는 글상자 · 서식 칸숨긴 글상자 · 서식 칸
OCR 하지 않는 쪽 (글자층 쪽 · OCR 끔 · 모델 없음)/Contents · 값으로 붙임/Contents · 값으로 붙임
OCR 한 쪽 · OCR 대기 쪽붙이지 않음 — OCR 이 읽음/Contents · 값으로 붙임 — 그림에 없어서 OCR 이 못 읽음
대기 모드(ocr.mode = deferred)에서는 OCR 대기 쪽의 보이는 주석이 OCR 이 끝날 때까지 본문에 없다. 그 쪽의 그림 속 글이 OCR 전까지 없는 지금 동작과 같다.

6-4. 블록 자리 · 출처

  • 쪽마다 글자층 줄 → 본문 밖 글 → OCR 줄(또는 OCR 구조 블록) 순서로 둔다. 본문 밖 글은 글자층과 OCR 사이(ocr_from 앞)에 끼운다.
  • 블록 종류는 paragraph 다. 글상자 하나가 블록 하나이고, 안쪽 줄바꿈이 있어도 블록을 나누지 않는다.
  • 출처(source)는 새 값 "extra"(blocks::SRC_EXTRA)를 쓴다. 부른 쪽이 본문 밖 글을 가려낼 수 있다. 머리말 · 꼬리말 판정과 제목 추론에는 넣지 않는다. 편집기로 덧붙인 글이라 쪽마다 되풀이되는 머리말과 성격이 다르다.
  • "텍스트층 없음" 판정(MIN_TEXT_CHARS = 20)에는 본문 밖 글자도 센다. 그러면 OCR 을 끈 2.pdf 는 legacy 폴백 대신 format: pdf 가 되고, 주석 글이 블록으로 나온다(정할 것 ③).

6-5. 다른 PDF 경로

  • legacy.rs pdf_text: 쪽마다 text 다음 줄에 extra 글을 잇는다. legacy 는 OCR 을 하지 않으므로 6-3 규칙상 모두 붙는다.
  • api.rs pdf_page_texts: 그대로 둔다(글자층만). 쪽 찾기는 글자층 글로 쪽을 맞추는 용도라서, 본문 밖 글을 섞으면 쪽 맞춤 점수가 흔들린다.
  • meta_info 의 text_chars: 그대로 둔다(글자층 글자 수라는 뜻을 지킨다).

7. docx · pptx · xlsx 설계

7-1. docx 메모

  • word/_rels/document.xml.rels 에서 comments 관계를 따라 word/comments.xml 을 연다. w:comment 마다 안의 문단 글을 모은다(각주를 읽는 코드와 같은 문단 모으기).
  • 각주처럼 문서 끝에 합성 제목 "메모"(synthetic)를 두고 그 아래 note 블록으로 넣는다. 출처는 "extra".
  • 작성자 · 날짜는 넣지 않는다. 사이냅과 같은 모양이고, 개인 정보가 본문에 섞이지 않게 하려는 것이다.
  • 답글(commentsExtended) · 새 메모 형식(commentsExtensible)은 이번 범위 밖이다. 글은 모두 comments.xml 에 들어 있다.

7-2. SmartArt (pptx · docx)

  • pptx: 슬라이드 관계 가운데 diagramData 를 따라 ppt/diagrams/dataN.xml 을 연다. 노트를 찾는 루프에 갈래 하나를 더하면 된다.
  • docx: 본문 관계의 diagramData 를 따라 word/diagrams/dataN.xml 을 연다. 본문에서 그 그림(dgm:relIds r:dm)이 나온 자리에 넣고, 자리를 못 찾으면 문서 끝에 둔다.
  • dgm:ptLst 의 dgm:pt 가운데 글이 있는 점(type 이 없거나 node)만 읽는다. parTrans · sibTrans · pres 는 연결선 · 모양을 위한 점이라 건너뛴다. 점 하나가 paragraph 블록 하나이고, a:p 가 여럿이면 줄바꿈으로 잇는다.
  • drawingN.xml(그려 둔 모양 캐시)은 읽지 않는다. 읽으면 같은 글이 data 와 두 번 들어간다.
  • pptx 는 그 슬라이드의 도형 글 다음에 둔다. 쪽 번호는 그 슬라이드 번호, 출처는 "extra" 다.

7-3. xlsx 메모 경로 (옵션과 무관한 고침)

  • docmodel/xlsx.rs comments() 와 legacy.rs 의 xlsx 메모는 파일 이름 정규식 대신 시트 관계(xl/worksheets/_rels/sheetN.xml.rels 의 comments · threadedComment)를 따라 찾는다. 관계가 없을 때만 지금 정규식으로 찾는다.
  • Excel 이 저장한 파일은 결과가 같다. openpyxl 등 다른 도구가 저장한 파일에서만 메모가 새로 나온다. 원래 읽어야 할 글이었으므로 버그 고침으로 보고 옵션 밖에 둔다.

8. 옵션

13. 정할 것

① 기본값켬(제안). 사이냅과 같은 글을 읽는 것이 목적이고, DocParse-rust 도 켬으로 정했다.
② 숨긴 PDF 글상자읽음(정함). 사이냅과 같다. OCR 쪽에서도 그림에 없으므로 /Contents 로 붙인다(6-3). DocParse-rust 도 같은 날 숨긴 글상자를 읽도록 고쳤다(그쪽 설계서 개정 2 · 커밋 a2a83e7) — 두 저장소가 같다.
③ OCR 을 끈 스캔 PDF 의 형식본문 밖 글이 20자 이상이면 legacy 폴백 대신 format: pdf 로 돌려준다(제안). 쪽 번호가 붙은 블록이 폴백 평문보다 낫다. 대신 "텍스트층 없음" 경고가 사라지므로, 이 경고로 스캔본을 가리는 곳이 있는지 확인한다.
④ 출처 값 "extra"새 출처 값(제안). SimpleRAG 가 source 로 청크를 거르거나 표시하는지 확인한다. 문제가 있으면 "parser" 로 두고 출처 구분은 포기한다.
⑤ 6-3 A 안 · B 안A(제안). 캐시를 건드리지 않는다. 스캔 쪽 주석 글의 정확도가 문제가 되면, B 를 캐시 판 올림과 함께 다음 판에서 다룬다.
⑥ "기밀" 오탐2.pdf 의 "국정원 산업기밀보호센터" 는 지금도 OCR 로 본문에 들어온다. 이 저장소는 문서에 있는 글을 읽을 뿐 거르지 않는다. 규칙 쪽(MpowerClassify)에서 다룰 일이다.
